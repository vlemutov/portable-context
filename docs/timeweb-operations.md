# Timeweb: обслуживание установленной памяти

Команды запускает агент из полного checkout Portable Context. `PRIVATE_STATE` — та же
приватная папка, которая использовалась при установке. Новая папка означает новую
установку, а не способ исправить старую. Секреты остаются локально и на ВМ владельца.

## Диагностика без передачи секретов

```text
python deploy/setup.py --state PRIVATE_STATE install-status
python deploy/setup.py --state PRIVATE_STATE timeweb-diagnostics
python deploy/setup.py --state PRIVATE_STATE https-check
```

`timeweb-diagnostics` читает API, записывает `timeweb-support.json` и показывает его путь.
В отчёте: выбранные тарифы/зона, стадия, ID ресурсов, наличие ресурсов, статусы публикаций,
коды отказов и результаты проверки при установке. Он **не включает** произвольные логи,
переменные контейнера, пароли, ключи, содержимое памяти и комплект восстановления.
Отчёт содержит идентификаторы облачных ресурсов; перед передачей пользователь может его просмотреть.
Проверка `https-check` отдельно проверяет текущий публичный вход и сервер через SSH.
Историческая успешная проверка из receipt не доказывает текущую доступность.

Если нужны сырые логи, получайте их отдельно в приватный файл, анализируйте локально и
передавайте только проверенные фрагменты. Не архивируйте всю папку `PRIVATE_STATE` для поддержки.
403 — повод проверить права; `hidden-by-api-key-policy` — отключить маскирование секретов
у установочного токена; 409 `no_free_node` — подобрать тариф; DNS-ошибка — ждать/продолжать
тот же ресурс. Ошибка не даёт права переключать регион, повышать цену или создавать дубликат.

## Обновление версии

Сначала агент получает полный **чистый** checkout опубликованного commit, проверяет CI
именно этого commit и читает изменения релиза. Приватная папка установки остаётся прежней.
Для обновления памяти и контроллера без изменения закреплённого исходника контейнера:

```text
python deploy/setup.py --state PRIVATE_STATE update
```

Для перехода на новый исходный commit, включая контейнер:

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-update --commit FULL_COMMIT
python deploy/setup.py --state PRIVATE_STATE timeweb-update --commit FULL_COMMIT --approve-plan REVIEWED_SHA256
```

Первый вызов только показывает план. После согласования операции агент передаёт его хэш.
Команда сохраняет тот же workspace, ВМ, бакет, приложение и домен; действующие сертификаты
и настройки контейнера не заменяются старыми локальными файлами. Контроллер на ВМ
координирует смену версии с продлением сертификатов. Затем выполняется штатное обновление
памяти с проверкой резервирования и HTTPS. Новые облачные ресурсы не создаются.

Публикация асинхронная: результат `pending` означает повторить **ту же** команду с тем же
commit/хэшем. Потерянный ответ POST не вызывает ещё один POST. При прерывании ресурсов
не удаляют. Пока исходник переключается, продление сертификатов ждёт завершения операции;
не оставляйте незавершённое обновление на длительный срок.

При окончательной ошибке сборки сначала диагностика. Только после разбора причины:

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-update --commit FULL_COMMIT --retry-failed
python deploy/setup.py --state PRIVATE_STATE timeweb-update --commit FULL_COMMIT --retry-failed --approve-plan RETRY_SHA256
```

План повторной публикации связан с наблюдаемым списком деплоев. Если список изменился,
получите новый план; новый запрос не разрешён, пока есть незавершённый деплой.
Нельзя вручную редактировать `deployment.json`, журналы или закреплённый commit контроллера.
Автоматический откат версии при неудачной сборке пока не реализован: сохраняйте ту же
установку и диагностируйте причину. Для первого незавершённого развёртывания используйте
`timeweb-retry-deploy` и `install --https`, а не команду обновления.

## Завершение теста и удаление

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-cleanup
python deploy/setup.py --state PRIVATE_STATE timeweb-cleanup --approve-plan REVIEWED_SHA256
```

Первый вызов ничего не удаляет. Агент показывает пользователю точный перечень и последствия.
**Удаляются память на ВМ, учётные записи OAuth, приложение, адрес IPv4 и бакет со всеми
версиями файлов и резервных копий.** Если данные нужны, до подтверждения сохраните проверенную
копию вне удаляемой установки. Комплект восстановления — ключи доступа, а не полная копия S3.

Команда использует ID из журнала этой установки и сверяет ресурсы. Подтверждение относится
к конкретному плану. После тайм-аута она сначала проверяет исчезновение ресурса; неоднозначный
DELETE автоматически повторно не отправляет. При `pending` повторите команду с тем же хэшем.
Удаление возможно и после прерванного обновления: план явно укажет его прекращение,
сверит прежнюю/новую версии и сохранённые ID. Исправлять сборку только ради удаления не нужно.
423 может означать требуемое провайдером подтверждение удаления: завершите его в кабинете,
не отключайте эту защиту без отдельного решения владельца.

Созданные установщиком проект, SSH-ключ и Git-подключение удаляются только когда проверка
не обнаруживает других ВМ/приложений/бакетов; дополнительно проверяется пустота проекта.
При сомнении общие настройки сохраняются и перечисляются как `retained` для отдельного разбора.
Предварительно существовавший проект, чужие ресурсы, аккаунт, баланс и API-токен не удаляются.
Это **не** команда «очистить весь аккаунт».

`timeweb-cleanup.json` хранит ход удаления и блокирует повторную установку в эту папку.
`complete` означает окончание прохода, а `all_planned_resources_absent` — отсутствие
всех запланированных ресурсов. Проверяйте оба поля и сохранённые элементы. Локальные
логи/ключи/комплект восстановления команда не стирает. Для следующего теста нужна новая
папка состояния и новый расчёт расходов. Строка уже использованного трафика в биллинге
может оставаться после удаления всех сервисов; это не доказательство оставшегося сервиса.

## Что ещё проверять живым клиентом

Инфраструктурная проверка не заменяет вход человека с passkey и согласие OAuth в Cursor.
После подключения: `memory_status`, совпадение workspace, выбранный маленький импорт с файлом,
чтение оригинала, повторный импорт без дублей и вики со ссылками на сообщения.
Отдельно проверяются SSE/длительные запросы, восстановление памяти и OAuth. Установка
таймера продления не означает, что выполнен тест принудительной ротации с прерыванием.

## Правила, закреплённые после пилота

| Область | Правило для установщика и агента |
| --- | --- |
| Права | Управление сервисами не равнозначно административным правам; проверьте 403 до платных шагов |
| Маскирование | `hidden-by-api-key-policy` нельзя записывать вместо секрета или считать обычным отличием cloud-init |
| Срок токена | Минимальный доступный срок; до истечения заменить токен контроллера, не отзывать сразу после установки |
| Цена | ВМ + отдельный IPv4 + App + S3 + запросы/трафик + время ожидания; бюджет теста не лимит провайдера |
| Тариф | Линейка по tags; одинаковые CPU/RAM/частота не означают одинаковую доступность |
| Зона | Явная availability zone из каталога; наличие тарифа не гарантирует свободных узлов |
| Запасной вариант | Только после однозначного отказа и в согласованных пределах цены/региона; без замены существующей ВМ |
| API | Разные версии создания/чтения App, реальные envelopes SSH и IPv4; clone URL с `.git` для обычного Git provider |
| Адрес | Отдельное выделение IPv4 с журналом намерения; после удаления ВМ адрес может остаться платным |
| Зависимости | После cloud-init проверить Python/venv/cron; ждать apt, не удалять lock-файлы |
| Сеть | SSH — администрирование; HTTPS — клиенты; никаких постоянных hosts/маршрутов ради подключения |
| DNS | Ограниченное ожидание последовательных успехов обычного DNS/HTTPS и продолжение того же приложения |
| Контейнер | Только EXPOSE 8080, собственный healthcheck, проверка конфигурации перед стартом |
| Готовность | build success, active и health 200 недостаточны; отличать заглушку, проверять OAuth и отказ анонимному MCP |
| Деплои | stopped — завершённая отменённая сборка; новый деплой только после разбора и явного плана |
| Обновление | Согласовать commit приложения, журналов и контроллера, не заменять сертификаты старыми |
| Данные | Постоянный диск ВМ, stateless edge, приватный S3 с версиями; права S3-ключа могут быть на весь аккаунт |
| Копии | Отдельные копии памяти и OAuth, проверка восстановления; recovery kit не копия всех объектов |
| Продление | Расписание не заменяет приёмочный тест ротации; учитывать срок облачного токена |
| Вход | Passkey/consent/чтение/запись/файлы проверять реальным клиентом, отдельно от инфраструктуры |
| Очистка | Точный план, подтверждение уничтожения копий, проверка отсутствия, сохранение местных доказательств |
| Поддержка | Отчёт по разрешённым полям, без raw logs/env/ключей/текстов памяти |
| Остатки | Сверять IPv4 и общие настройки; не путать биллинговую историю с работающими сервисами |
| Терминал | JSON должен выводиться и при Windows cp1252; русские имена не должны ломать диагностику |

### Потерян ответ на создание HTTPS-приложения

`timeweb-retry-deploy` повторяет сборку **существующего** приложения. Для потерянного
ответа на создание сначала проверьте полный список приложений. Если нужное приложение
найдено, используйте `timeweb-reconcile --stage app --resource-id ID` и продолжите ту же
установку. Не очищайте `submitted` вручную и не создавайте новую папку состояния.

Если приложение не найдено после повторных проверок, покажите пользователю остаточный
риск: первый запрос может завершиться поздно и создать дубль. После его согласия:

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-retry-create
python deploy/setup.py --state PRIVATE_STATE timeweb-retry-create --approve-plan REVIEWED_HASH
python deploy/setup.py --state PRIVATE_STATE install --https
```

Команда разрешает один POST создания приложения с тем же телом запроса. Подтверждение
действует 15 минут; полный список проверяется при подтверждении и перед POST. При
изменении списка или истечении срока заново просмотрите план. Потеря ответа при повторе
снова требует отдельного решения. Старое намерение и подтверждение сохраняются в журнале.
Если появилось приложение с тем же именем или Git provider, автоматический повтор
блокируется. После повторного создания и при продолжении установки проверяются возможные
дубли; их обнаружение останавливает работу без удаления. Отсутствие дубля в момент проверки
не гарантирует, что первый запрос никогда не завершится: повторите диагностику после установки.

Автоматическая замена истекающего токена и общий счётчик фактических расходов пока не реализованы.
Доступность тарифа и результаты установки на одном аккаунте не являются SLA провайдера.
