# Чистая установка второй памяти через Cursor

Цель: пройти обычные инструкции с другого компьютера, без истории разработки и готовых
конфигураций. Создаётся новая пустая память в отдельном проекте того же аккаунта Cloud.ru.
Действующая память продолжает работать. Новый аккаунт Cloud.ru не требуется.

Это испытание 1.0-preview, а не опубликованный релиз 1.0. Cursor пока экспериментальный клиент.
Проверка кода и локальные тесты двух установок не заменяют фактический облачный проход.

## Старт

Открой пустую папку и новый чат в Cursor Desktop с доступом к терминалу и файлам. Передай
агенту ссылку на **конкретный commit** этого репозитория и такой запрос:

> Помоги с нуля установить Portable Context по этой версии репозитория: ССЫЛКА_НА_COMMIT.
> Прочитай START-HERE.md и skills/portable-context/SKILL.md именно этой версии.
> Я работаю в Cursor Desktop на другом компьютере. Хочу создать отдельную новую память
> в новом проекте моего существующего аккаунта Cloud.ru. Другую действующую память
> и её ресурсы не изменяй. Веди меня по шагам от подготовки компьютера до входа по
> HTTPS/OAuth, первого выбранного импорта с файлом и чтения результата.
> Выполняй технические шаги сам, где можешь; затраты согласуй до создания ресурсов,
> секреты помоги ввести локально. Если инструкция или поддержка Cursor не позволяют
> продолжить, сохрани обезличенный отчёт о блокере, не придумывай обходной установщик.

Агент получает полный checkout выбранного commit. Не скачивай отдельно скилл из другой ветки.
Не переноси с прежнего компьютера приватную папку установки, ключи, токены, recovery kit
или рабочий MCP-конфиг. Для теста владелец входит в свой облачный аккаунт обычным способом.
Не нужно заранее вручную создавать ВМ, бакет или контейнер — сначала план установщика.

## Что должен проверить агент

1. Прочитать [онбординг](../skills/portable-context/references/onboarding.md), выбрать маршрут
   «создать ещё одну память», подготовить Python/OpenSSH и отдельную папку установки.
2. Выбрать новый Project ID, отдельные credentials, получить каталог/tenant, показать планы
   ВМ/S3 и HTTPS с расходами. Все ресурсы относятся к новому проекту, каждый CREATE сохраняет receipt.
3. Пройти штатную установку, owner login и комплект восстановления. Настроить
   [Cursor OAuth](../skills/portable-context/references/connection.md#cursor-desktop--экспериментальный-чистый-тест)
   через новый issuer. Нативный HTTPS Cursor ещё требует наблюдаемой проверки.
4. Сверить workspace ID, выбрать небольшой реальный диалог/официальный экспорт и файл.
   Импорт истории Cursor сам по себе не поддержан: не обещать чтение её закрытого хранилища.
   Прочитать сообщение, паспорт файла и оригинал; повторить импорт без новых сообщений/редакций.
5. Проверить возобновление передачи файла, вики со ссылками и подключение второго агента
   к этой же тестовой памяти. Не объявлять весь сценарий завершённым по одному memory_status.

## Результат для разработчика

Сохрани приватно commit, ОС/архитектуру, версию Cursor, workspace ID, пути state и receipts,
этапы и их результаты. Для передачи достаточно обезличенных ошибок, ожидаемого/фактического
поведения и версии. Не включай credentials, коды входа, токены, cookie, Terraform state
или содержимое комплекта восстановления. Отделяй проблему инструкции от ошибки приложения
и ограничения клиента. Любая необходимая правка должна попасть в репозиторий перед повтором.

Не удаляй тестовые облачные ресурсы автоматически после прохода: сохрани перечень и план
завершения для владельца. За время теста оплачиваются отдельные ресурсы.
