# Чистая установка Timeweb через Cursor

Этот сценарий не требует предыдущего чата с разработчиком. Он подходит для Windows,
macOS и Linux с Python 3.11+ и OpenSSH. Cursor должен иметь доступ к терминалу и файлам.
На новой установке подтвердите вход вызовом `memory_status` из самого Cursor.

Отправьте в новый чат Cursor:

> Помоги установить мою новую независимую память Portable Context в Timeweb Cloud.
> Репозиторий: https://github.com/vlemutov/portable-context/tree/feature/timeweb-installer.
> Получи полный checkout этой ветки, зафиксируй commit и проверь, что CI для него завершился успешно.
> Прочитай START-HERE.md, skills/portable-context/SKILL.md и маршрут Timeweb, на который он ссылается.
> У тебя нет контекста разработки: следуй опубликованным инструкциям и штатным командам.
> Используй новый отдельный проект и новую приватную папку установки. Существующие памяти не меняй.
> Технические шаги выполняй сам; спрашивай меня только о необходимых предпочтениях и ручных действиях.
> До создания ресурсов покажи полную стоимость и согласуй бюджет. Токен помоги ввести локально, не в чат.
> После каждого этапа сообщай, что уже работает, чего ждём, сколько стоят выделенные ресурсы и как продолжить эту же установку.
> Открой первый вход в системном браузере. До импорта объясни, как будет доставлен выбранный диалог.
> Проведи меня до входа по HTTPS/OAuth в Cursor, выбранного небольшого импорта с файлом,
> чтения результата и повторного импорта без дублей. После ошибки продолжай ту же установку;
> не удаляй ресурсы автоматически. Если штатный путь не работает, собери безопасную диагностику
> и объясни блокер, не подменяя установщик собственными скриптами.

Для воспроизводимого отчёта сохраните точный SHA выбранной ветки. Если CI ещё выполняется,
дождитесь его до платного шага. Новый тест не должен использовать рабочие ключи, конфиги MCP
или папку старой установки, перенесённые с компьютера разработчика.

Агент готовит локальную памятку: commit, ОС/архитектура, версия Cursor, private state,
адрес памяти, workspace ID и результаты каждого шага. Секреты в эту памятку не копируются.
Для второго клиента подключают тот же endpoint и проверяют тот же workspace, не создают ещё одну ВМ.

Приёмка состоит из отдельных результатов:

1. Установка и повтор команды не создают новых облачных ресурсов.
2. DNS и HTTPS работают через обычное подключение, включая используемый VPN, без hosts/маршрутов.
3. Человек вошёл через passkey и разрешил OAuth; `memory_status` вызван из Cursor.
4. Выбранное сообщение и файл сохранены, прочитаны обратно; второй импорт не увеличил счётчики.
5. Вики ссылается на источники, оригинал файла доступен, SSE/длительный вызов не обрывается.
6. Проверены копии памяти и OAuth; комплект восстановления сохранён отдельно от ВМ.
7. Диагностика читаема и не содержит секретов. Завершение теста — согласованный план очистки
   либо явно принятая стоимость хранения до следующей сессии.

Обновление на **другой** опубликованный commit и принудительная ротация сертификатов —
отдельные проверки. Повторная установка той же версии не заменяет их.
