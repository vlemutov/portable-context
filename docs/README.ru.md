# Portable Context: начало работы

Версия 0.2: общая память, которой ты управляешь через разговор с любым подключённым агентом.
Код публичный; личные архивы и знания хранятся отдельно в выбранном тобой каталоге или сервере.

После подключения скилла и MCP можно попросить:

> Объясни, какие источники тебе доступны и как пользоваться этой памятью.
>
> Перенеси обсуждения проекта Atlas вместе с ответвлениями.
>
> Создай вики проекта, выдели решения и свяжи связанные темы.
>
> Продолжи работу другого агента, добавь новые разговоры и обнови граф.

Все клиенты должны подключаться к одному хранилищу. `memory_status` показывает его идентификатор:
одинаковый скилл в разных приложениях сам по себе не объединяет разные папки памяти.

Что уже работает:

- Импорт Claude, ChatGPT, Telegram, активности Gemini и локальных JSONL Codex.
- Хранение оригиналов, редакций и веток; защита от повторной загрузки тех же сообщений.
- Поиск по тексту, Markdown-переписки и редактируемые заметки для Obsidian.
- Предпросмотр источника и импорт выбранных разговоров через MCP; остальные не сохраняются.
- Задачи переноса и обогащения с сохранением прогресса: другой агент может продолжить работу.
- Структурные связи ответов, форков, проектов и вложений из явно переданных исходных данных.
- Смысловые связи и страницы вики, которые создаёт подключённый агент с указанием источников.
- Версии страниц, защита от устаревших записей и сохранение ручных правок.
- Защищённый токеном HTTP MCP для совместимых клиентов; локальное подключение через stdio.
- Очередь доставки с нескольких серверов, использующая те же задачи импорта.

В [README](../README.md) есть команды установки, импорта и подключения. Начни с `init`, затем
подключи источник и скилл, затем попроси агента выполнить импорт. Для серверных локальных файлов
нужно один раз разрешить нужный каталог; для данных на стороне клиента агент использует
собственные инструменты истории и передаёт выбранные записи. [Подробный сценарий](user-journey.md)
показывает обе возможности. Программа сама не отправляет архивы сторонней модели: осмыслением
занимается тот агент, которому ты дал команду.

MCP не предоставляет историю аккаунта автоматически. Если агент не может её получить,
понадобится официальная выгрузка. Для Gemini используется Takeout; Antigravity не нужен.
Подключение к конкретной установке Ouroboros/Hermes/OpenClaw всё ещё требует доступного читателя
истории или адаптера. Общий механизм приёма, импорта и обогащения для них уже реализован.

Не реализованы полный экспорт нового постраничного хранилища Codex, готовые нативные читатели
истории всех агентов, фоновая модель, смысловой поиск по эмбеддингам и анализ вложений. Смысловой
граф уже поддерживается: его создаёт и обновляет агент по команде. Реальные архивы аккаунтов
и качество работы разных моделей ещё требуют проверки. [Матрица возможностей](connectors.md)
отделяет реализованное от будущей работы.

Постоянный сбор не включается при установке. Очередь и общий механизм импорта готовы, но
сборщик на конкретном источнике нужно настроить отдельно. Автоматическое сохранение сообщений
и автоматическое обновление смыслового графа — разные режимы.

Сохраняй каталог памяти отдельно от публичного GitHub. Он содержит исходные переписки,
вложения внутри ZIP и все сохранённые редакции. Резервная копия нужна для всего каталога,
а не только для видимых Markdown-файлов.
