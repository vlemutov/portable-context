# Timeweb: установка в своём аккаунте

Экспериментальный адаптер единого установщика. Он создаёт ВМ для памяти, приватный
S3-бакет для оригиналов и резервных копий, контейнерный HTTPS-вход с техническим
доменом. SQLite, OAuth и restic работают на ВМ с постоянным диском. Контейнер не
хранит базу и не получает API-токен облака. Домен покупать не нужно.

Реально проверены полный инфраструктурный путь ВМ → S3 → mTLS → HTTPS, обнаружение OAuth,
отказ анонимному MCP, проверка копий памяти/OAuth, recovery kit и повтор установки без новых
ресурсов. На отдельном диагностическом приложении проверены OAuth, SSE и передача файлов.
17 ноября 2026 на новой установке проверены вход владельца с passkey и consent,
нативный OAuth/MCP Codex на Windows ARM64, импорт двух синтетических сообщений с raw/executor,
повтор без дублей, файл с проверенной копией S3, вики с точными источниками и обновление
на тех же ресурсах с чтением данных после него. Это не проверка Cursor или массового
переноса личного архива. 18 ноября штатная очистка удалила весь тестовый комплект,
включая IPv4, версии S3 и пустой проект; отсутствие ресурсов проверено через API. Не выдавайте
локальные тесты с имитацией API за проверку всего облачного пути.
До объединения используйте ветку `feature/timeweb-installer`, затем сохраните её точный commit.

## Начните с разговора

Агент спрашивает, есть ли уже память. При новой памяти предлагает Cloud.ru, Timeweb,
свой сервер или локальный старт. Для Timeweb человеку нужны аккаунт, оплата и API-токен
с правами на создание выбранных ресурсов. Токен вводят в скрытом локальном запросе,
не в чат. До создания агент показывает выбранные тарифы и получает согласие на расходы.

Сначала прочитайте [правила биллинга](timeweb-billing.md): почасовой расход облачного
баланса и автопополнение с карты — разные операции. Привязка карты/СБП может включить
автоплатёж на месячную сумму. Согласование «теста до 30 ₽» без проверки автоплатежа
не ограничивает списание с карты. До платных действий выясните оба вида расходов.

Опция «Ограниченные права для токена» может запрещать административные эндпоинты даже
при разрешённом управлении всеми сервисами. В живом тесте такой токен получал 403 при
создании проекта и чтении баланса. Можно заранее создать проект в кабинете и указать
его `project_id`, сохранив ограниченные права, либо использовать токен владельца без
этой опции для автономного создания проекта. Не обещайте, что права на все сервисы
равнозначны правам администрирования аккаунта.

Рекомендуйте минимальный доступный срок действия токена: в кабинете пилота — 30 дней.
Перед выбором проверьте варианты, показанные пользователю. Этот же токен сейчас нужен
на ВМ для автоматического продления сертификатов; до его истечения потребуется
замена в контроллере. Короткий срок ограничивает длительность доступа, но не его
полномочия. Автоматическая смена или разделение установочного и рабочего токенов
пока не реализованы; не отзывайте рабочий токен после установки без замены.

Для автономной установки отключите у установочного токена «Скрывать пароли и другие
чувствительные данные». Иначе API заменяет cloud-init и ключи S3 строкой
`hidden-by-api-key-policy`: сверить ВМ и настроить резервные копии невозможно.
Это отдельная настройка от «Ограниченные права для токена». Значения секретов вводятся
и сохраняются приватно; агент не выводит их в чат, отчёты или Git. Разрешение удалять
сервисы без подтверждения в Telegram для установки не требуется.

На Windows, macOS и Linux нужны Python 3.11+ и OpenSSH. В отдельном окружении установите
полный checkout с `pip install -e ".[mcp,deployment]"`. Terraform и Docker на компьютере
для Timeweb не нужны. Серверный профиль: Ubuntu 24.04 AMD64, минимум 2 ГБ RAM и 20 ГБ диска.

Ниже команды выполняет агент. `PRIVATE_STATE` — новая постоянная приватная папка **вне
репозитория**, `OPTIONS.json` — подготовленный агентом файл без секретов. Агент подставляет
абсолютные пути и корректное цитирование оболочки. В PowerShell перед заключённым в кавычки
путём Python нужен `&`; не копируйте синтаксис Bash в PowerShell.

```text
python deploy/setup.py --state PRIVATE_STATE init --mode timeweb
python deploy/setup.py --state PRIVATE_STATE credentials
python deploy/setup.py --state PRIVATE_STATE catalog
python deploy/setup.py --state PRIVATE_STATE configure --file OPTIONS.json
python deploy/setup.py --state PRIVATE_STATE plan
python deploy/setup.py --state PRIVATE_STATE apply --approve-plan REVIEWED_SHA256
python deploy/setup.py --state PRIVATE_STATE install --https
```

Файл параметров содержит:

| Поле | Как выбрать |
| --- | --- |
| `server_preset_id` | Действующий тариф Linux ВМ в российской локации из `catalog` |
| `storage_preset_id` | Тариф S3 в российской локации из `catalog` |
| `app_preset_id` | Тариф backend App Platform в российской локации из `catalog` |
| `os_id` | Ubuntu 24.04 из `catalog` |
| `availability_zone` | Явная зона ВМ из `catalog.locations`, принадлежащая локации выбранного тарифа |
| `ssh_cidr` | Согласованный IPv4 CIDR для администрирования ВМ, обычно текущий IP/32 |
| `project_id` | Необязательно: существующий отдельный проект; иначе создаётся новый |
| `source_url` | Публичный clone URL этого репозитория или проверенного форка, например `https://github.com/vlemutov/portable-context.git`; установщик добавляет `.git`, если суффикса нет |
| `source_branch` | Ветка, содержащая установщик и `deploy/timeweb-edge` |
| `source_commit` | Полный опубликованный SHA выбранной версии, не `latest` |
| `dns_timeout` | Необязательно: 1800 секунд по умолчанию, диапазон 60–3600 |

Не угадывайте ID тарифов и не переносите ID из чужого аккаунта. План показывает
текущие цены доступных тарифов; отдельно учитываются IP, трафик и операции S3.
Проверка квот Timeweb пока не подтверждается автоматически: наличие тарифа в каталоге
не доказывает доступность ресурсов или достаточный баланс. API-отказ оставляет состояние
для продолжения. Установщик не задаёт лимит расходов в аккаунте.

Для S3 API может выдать общие ключи аккаунта, а не отдельного пользователя бакета.
Это обозначается в плане. Они хранятся приватно и передаются только на ВМ владельца;
не обещайте изоляцию прав по бакету. Сам бакет приватный; версионирование проверяется и
включается перед установкой памяти. Restic шифрует резервные копии, включая оригиналы.

ВМ принимает SSH только из выбранного CIDR. Порт 9443 доступен для контейнера,
но обслуживается только с взаимной TLS-аутентификацией. Подключение агентов идёт через
публичный HTTPS/OAuth и не зависит от SSH CIDR. При смене сети для обслуживания ВМ
может понадобиться отдельное изменение firewall; обычному пользователю MCP оно не нужно.

## Ожидание и продолжение

### Запасные варианты ВМ

Выбирайте не только CPU/RAM/диск, но и линейку по `tags`: например, `msk_nvme` —
Premium в Москве, `ultra_msk_nvme` — Ultra. Их частота и внутреннее имя конфигурации
могут совпадать. Каталог не сообщает наличие свободных ресурсов. `no_free_node`
относится к выбранной конфигурации, а не ко всему городу или провайдеру.

После подтверждённого отказа `409 no_free_node`, `404 preset_not_found` или
`400 servers_is_run_out_error` при создании ВМ агент
подбирает варианты. По умолчанию поиск ограничен текущей локацией и текущей ценой;
расширение региона и предела цены должно соответствовать согласию пользователя:

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-vm-options --location ru-3 --max-monthly-price REVIEWED_MONTHLY_VM_PRICE
python deploy/setup.py --state PRIVATE_STATE timeweb-select-vm --preset-id SELECTED_ID --availability-zone SELECTED_ZONE
python deploy/setup.py --state PRIVATE_STATE timeweb-select-vm --preset-id SELECTED_ID --availability-zone SELECTED_ZONE --approve-plan SELECTION_SHA256
python deploy/setup.py --state PRIVATE_STATE apply --approve-plan NEW_PLAN_SHA256
```

Агент показывает разницу ежемесячной цены и учитывает IP/S3/HTTPS отдельно. При заранее
согласованных пределах агент может сам выбрать вариант и передать хэши; иначе сначала
согласовывает новую цену/регион. Команда выбора меняет только ещё не созданную ВМ,
сохраняет проект и SSH-ключ, историю отказов и точку продолжения. Существующая ВМ,
неоднозначный тайм-аут, неполный список ВМ или совпадающая ВМ в аккаунте блокируют
переключение. Ошибки прав и валидации не считаются нехваткой мощностей. Массового
автоматического перебора с платным созданием и удаления ресурсов нет.

### `400 servers_is_run_out_error` и регион, которого нет в панели

В пилоте Ubuntu 21 ноября 2026 API дважды отказал в создании тарифа 6771
(`ru-4`, `ekb-1`, Cloud EKB 30). Проект и SSH-ключ созданы; ВМ и последующие
IP/S3/App не созданы. Екатеринбург присутствовал в каталогах API, но пользователь
не видел его в панели. Это наблюдение, а не подтверждение причины отказа.
Официальная расшифровка кода не установлена: не объявляйте превышение квоты,
необходимость верификации личности или нехватку мощностей доказанными.

`/api/v2/locations` — общий каталог; его наличие вместе с тарифом не подтверждает
возможность заказа. План и варианты явно показывают `capacity: unknown` и
`panel_visibility: unknown`. Если тариф содержит собственную `availability_zone`,
установщик пересекает её с зонами региона. Если таких сведений нет, он не угадывает
доступность. Москва `msk-1` отмечена как зона успешного пилота, без гарантии текущей
доступности или доступности всех её тарифов. Другие зоны не запрещены навсегда.

При таком отказе:

1. Сохраните ту же private state и выполните `install-status`/`timeweb-diagnostics`.
   Повторный `apply` больше не отправляет тот же POST: отказ сохранён у самой ВМ,
   даже если последующая ошибка изменила `last_error`. Старые журналы preview.6 поддержаны.
2. `timeweb-vm-options` исключает ранее отклонённые пары тариф/зона этой установки.
   Отказ одной пары не исключает весь регион. Пустой список при прежнем потолке цены
   не доказывает лимит аккаунта: другие регионы могут быть значительно дороже.
3. Если регион отсутствует в панели, не выбирайте его только потому, что он дешевле
   в API. Покажите альтернативу, доступную пользователю в панели, и согласуйте регион,
   линейку, полную стоимость и возможное автопополнение. Например, поиск в Москве
   использует `--location ru-3`, в Петербурге — `--location ru-1`.
4. Выполните `timeweb-select-vm` с предварительным просмотром и подтверждением,
   затем `apply` с новым хэшем плана. Команда перед выбором сверяет полный список ВМ;
   возможный запоздалый сервер или неполная выдача блокируют замену. Проект/ключ сохраняются.
   Осознанный повтор прежней пары тоже требует выбора и подтверждения плана;
   preview помечает его `retry_same_selection: true`. Не используйте это для цикла повторов.
5. Если отказ повторяется и на другом согласованном варианте, остановите перебор и
   подготовьте обращение в поддержку с кодом, временем, тарифом, зоной и `response_id`.
   Отправку обращения выполняет пользователь либо агент по отдельному поручению.

Новые неудачные запросы сохраняют отдельные метки времени и безопасный UUID `response_id`.
Тело ошибки и `message` по-прежнему не записываются: они могут содержать секреты.
Утраченные старым установщиком сведения не восстанавливаются и не требуют нового
платного запроса ради диагностики. Никакие ресурсы при отказе автоматически не удаляются.

API может создать ВМ без публичного IPv4. Установщик отдельно выделяет один адрес
с сохранением намерения до запроса; после потерянного ответа сначала сверяет адреса
той же ВМ, не покупает второй IP. После появления сети проверяет Python/venv/cron и
при необходимости устанавливает зависимости, ожидая штатных блокировок apt.

### Продолжение установки

`active` у провайдера ещё не означает, что домен готов. Установщик отдельно проверяет
системный DNS и обычный HTTPS с проверкой сертификата. Нужны три успешных проверки подряд.
При DNS-ошибке он ждёт до 30 минут; ничего не прописывает в hosts, маршруты, VPN или DNS.
В пилоте первое обычное HTTPS-подключение получилось примерно через восемь минут после
запуска. Это наблюдение одного теста, не гарантированный срок Timeweb.

При тайм-ауте, ошибке API, квот или сборки ресурсы **сохраняются и продолжают оплачиваться**.
Агент сообщает стадию, сохранённые ID, стоимость удержания и следующий шаг. Не создавайте
новый state, приложение или память. После устранения причины повторите:

```text
python deploy/setup.py --state PRIVATE_STATE install-status
python deploy/setup.py --state PRIVATE_STATE install --https
```

Если ответ на создание ресурса потерян, автоматического повтора POST не будет. Агент
сверяет ресурс в аккаунте (имя, проект, назначение) и передаёт проверенный ID:

```text
python deploy/setup.py --state PRIVATE_STATE timeweb-reconcile --stage STAGE --resource-id REVIEWED_ID
```

Стадии: `project`, `ssh_key`, `server`, `bucket`, `git`, `app`. После продолжения дополнительно
проверяются идентичность ресурса и конфигурация. Не подставляйте ID другой памяти.
Если потерян ответ публикации или сборка завершилась ошибкой, сначала проверьте существующие
деплои. `timeweb-retry-deploy` выдаёт план допуска повторного деплоя **того же приложения**;
после проверки передайте его хэш через `--approve-plan`, затем повторите `install --https`.
При незавершённом деплое новый запрос не разрешается. Отдельного автоматического удаления нет.
Это работает и при ошибке самой первой сборки, когда DNS и TLS ещё не настроены:
повторяется сборка первоначального приложения, а не создание нового.

При `400 url_is_not_valid_exception` на создании обычного Git-подключения проверьте
clone URL: в живом тесте веб-адрес без `.git` был отклонён. Исправленный установщик
нормализует суффикс. Для ранее отклонённого запроса он сохраняет историю изменения
хэша и продолжает ту же установку, только если отказ однозначный и подключения ещё нет.
При потерянном ответе нормализация не разрешает новый POST. Рабочие подключения не заменяются.

## Вход, обновление и восстановление

После успешной установки `https-installed.json` содержит адрес и workspace ID,
`client-https.json` — параметры MCP, `owner-enrollment.json` — путь к приватному
одноразовому входу. Агент помогает владельцу создать passkey и подключиться через OAuth.
Проверяет реальный `memory_status`, совпадение workspace ID и выбранный первый импорт.

Комплект восстановления сохраняется приватно отдельно от ВМ; его значения не показывают
в чате. Проверяются восстановление restic и отдельная копия OAuth. Сертификаты связи
контейнер–ВМ продлевает таймер на ВМ, поэтому её контроллеру нужен сохранённый API-токен
Timeweb. Отзыв токена требует обновления настроек контроллера.

`update` обновляет память и код контроллера на прежней ВМ, проверяет прежний HTTPS-вход.
Для смены закреплённого commit контейнера используйте `timeweb-update`, для безопасного
отчёта — `timeweb-diagnostics`, для удаления установки — `timeweb-cleanup`.
Порядок, планы подтверждения и ограничения описаны в
[инструкции обслуживания](timeweb-operations.md). Не редактируйте журналы вручную.
Для чистой новой установки в Cursor есть [самодостаточный стартовый запрос](timeweb-clean-test.md).

Официальные сведения: [App Platform](https://timeweb.cloud/docs/apps/deploying-with-dockerfile),
[автоматический домен](https://timeweb.cloud/docs/apps/domain),
[создание сервера](https://timeweb.cloud/docs/cloud-servers/manage-servers/create-server),
[S3](https://timeweb.cloud/docs/s3-storage/manage-storage/create-bucket).
