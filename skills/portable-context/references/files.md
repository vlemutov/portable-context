# Файлы и проекты: фиксируй контекст при экспорте

## Что должен получить человек

После команды «сохрани этот проект» память содержит входную страницу проекта, выбранные диалоги,
паспорта их файлов и доступные оригиналы. Агент сообщает, что сохранилось, что отсутствует и что
ещё не извлечено. Пользователь не должен вручную классифицировать каждый технический идентификатор.

До выгрузки посмотри контекст исходного диалога: зачем нужен файл, кто его предоставил, это исходник,
черновик, результат или справочный материал, какое решение определяет его актуальность. Сохраняй
известное; не угадывай «финальный» по названию. По умолчанию бери вложенные исходники и результаты
из выбранного пользователем диалога. Упоминание рабочего каталога не разрешает копировать весь диск,
кеши, зависимости, секреты или чужие проекты. Дополнительные проектные файлы включай только в
пределах выбранного пользователем объёма и привязывай к реальному сообщению, объясняющему их роль.

## Запись при экспорте

Нормализованное сообщение может дополнительно содержать:

```json
{
  "memory_project": {
    "id": "atlas",
    "name": "Atlas",
    "basis": "user_selection",
    "summary": "Разработка сайта Atlas. Сначала читать brief.md, затем последние решения в wiki."
  },
  "attachments": [{
    "file_id": "native-file-id-if-exposed",
    "path": "/client/project/brief.md",
    "name": "brief.md",
    "role": "input",
    "purpose": "Требования к сайту, предоставленные пользователем",
    "status": "unknown",
    "metadata_basis": "user_statement",
    "sha256": "only-an-actual-sha256-of-available-bytes"
  }]
}
```

Это дополнительные поля, а не полное сообщение. Поле `sha256` опусти, если байтов нет.
`project={id,name}` остаётся только для родного проекта платформы. `memory_project.basis` —
`user_selection` или `agent_inference`; ID повторно используется во всём workspace, поэтому не
сливай разные проекты под общим ID. Без сведений о проекте создаётся входная страница диалога
со статусом `unclassified`. При последующей классификации используй `update_project` с текущей
версией: это не переписывает исходные сообщения и не выдаёт решение агента за родные метаданные.

Паспорт создаётся в одной транзакции с сообщением, даже если файл недоступен. Он сохраняет полный
исходный объект вложения, точные ключ/ревизию сообщения и место вложения в сообщении. Байты
привязываются к этому наблюдению отдельно. Один путь с изменёнными байтами требует новой ревизии
источника; нельзя незаметно заменить оригинал старого наблюдения. Один SHA256 хранится один раз,
даже если его используют несколько файлов. Одинаковое имя не означает одинаковый документ.

Если уточнение назначения/актуальности появилось позже, `annotate_file` сохраняет его отдельным
слоем паспорта: purpose, role, status, kind, точные sources, actor и expected_version (0 при создании).
Роли: input/output/reference/unknown; статусы: unknown/draft/current/approved/obsolete/superseded.
Это не меняет исходные сообщения. `read_file` возвращает версии и признак устаревших цитат;
`check_memory` показывает такие пробелы. Для уже импортированных старых файлов используй этот
путь, вместо переписывания истории ради красивого паспорта.

## Быстрый путь: MCP

1. `stage_records` → `run_import` до завершения: каталог и входные страницы уже созданы.
2. `list_files(project_id)` → получить ID наблюдений (`occurrences[].id`). Пагинируй список;
   внутри списка показаны только пять наблюдений, полная история — `read_file(file_id,offset)`.
3. `store_attachment(occurrence_id,content_base64,expected_sha256)` для файла до 8 МиБ.
   Для больших файлов скопируй только выбранный файл в разрешённый каталог сервера и передай
   `server_path` (до 512 МиБ). Путь компьютера клиента не является путём сервера.
4. Проверить `local_stored` и `s3.status` по отдельности. `verified` означает скачивание объекта
   из S3 и совпадение SHA256. При `failed` локальная копия сохранена; повтори ту же передачу.
5. `memory_status.catalog` показывает недостающие оригиналы во всём workspace. Сверь выбранные
   файлы отдельно, чтобы незагруженные файлы другого проекта не блокировали текущую работу.

Инструменты не скачивают URL и не открывают путь из архивного сообщения автоматически.

## Надёжный путь: снимок на компьютере источника

В 0.5 предпочтителен готовый [локальный клиент](client.md): он выбирает Claude Code/claude.ai,
проверяет содержимое, собирает пакет и доставляет его через MCP с продолжением после обрыва.
Ниже — низкоуровневый путь для уже подготовленных нормализованных записей других источников.

Если исходные файлы временные или загрузка может прерваться, сначала собери пакет на клиенте.
Нужен установленный Python-пакет Portable Context. Агент заранее сохраняет **только выбранные**
нормализованные сообщения в JSON-массив или JSONL, дополняя контекстом проекта и файлов.

Одна строка, одинаковая форма для PowerShell, macOS и Linux (подставь действительные пути):

```text
python -m portable_context.capture create --records /private/selected.json --destination /private/capture-atlas --source-root /private/project --project-id atlas --project-name Atlas --project-summary "Назначение проекта и порядок чтения"
```

`--source-root` можно повторить. Указывай узкие каталоги с выбранными файлами. Экспортёр не обходит
каталог: он читает только `attachments[].path` выбранных сообщений внутри разрешённых корней.
Пакет содержит `records.json` и дополнительные части `records-N.json` по необходимости,
`manifest.json`, оригиналы `blobs/<sha256>` и локальный каталог
`catalog/vault/projects/`, `catalog/vault/files/`. Паспорт и входная страница существуют уже сейчас,
до передачи в облако. Отсутствующие/неразрешённые/слишком большие файлы перечислены в записях
с причиной. Байты соответствуют моменту снимка; неизменность файла со времени старого сообщения
не предполагается. Для документов более 512 МиБ сообщи ограничение, не заявляй полный перенос.

Предпочитай `portable_context.client send` из client.md: путь сервера выяснять не нужно.
Для ручного альтернативного пути перенеси директорию в разрешённый imports-каталог через SSH/SFTP.
Затем `import_file_capture(server_directory)` возобновляет импорт всего выбранного пакета.
Альтернатива без MCP, на самом сервере:

```text
python -m portable_context.capture import --directory /private/imports/capture-atlas --home /private/memory --source-root /private/imports
```

Повторный импорт того же пакета не дублирует сообщения и байты. Для повтора доставки используй
тот же пакет. В 0.5 время сборки хранится в manifest/receipt и не меняет ревизии неизменённых записей.
Храни пакет вне публичного
репозитория; после подтверждённой загрузки и резервного копирования его можно удалить по решению владельца.

## Хранение, извлечение, чтение

SQLite хранит каталог/историю/индекс, `originals/<sha256>` — локальную копию оригинала. Если
`PC_ATTACHMENT_S3_CONFIG` указывает на приватный JSON конфигурации S3 из инструкции deployment,
оригиналы также записываются в `attachments/<sha256>`. Установщик облака настраивает это сам,
используя существующий приватный бакет и credentials. Не передавай секреты в вызовах MCP.
Требуются права List/Head/Get/Put на эти объекты, а не только на `backups/`.

Ежедневный backup ZIP включает согласованный снимок SQLite и все зарегистрированные оригиналы,
в том числе вложения. Отдельный объект S3 не заменяет бэкап. Пока это полные архивы, не
инкрементальные: ежедневное копирование большого корпуса увеличивает расход места. Установщик
оставляет семь локальных архивов, удалённые архивы автоматически не удаляет. Не обещай экономию
от дедупликации между разными ZIP. Автоматическое удаление/retention в S3 требует отдельной политики владельца.

UTF-8 txt/md/json/jsonl/csv/log/yaml и некоторые исходники до 2 МиБ автоматически индексируются
фрагментами с символьными смещениями. PDF, Office, изображения, аудио и другие форматы остаются
состоянием `needs_extractor`: оригинал сохранён, содержание ещё не прочитано. Подключённый агент
использует доступный ему парсер/OCR и вызывает `add_file_excerpts(sha256,chunks,method,actor)`.
У каждого фрагмента — текст и `locator` (страница, лист/ячейки, кадр/время, область изображения).
Называй фактический метод, отмечай неуверенное распознавание. Пересказ не выдавай за дословную цитату.

Поиск: проект → паспорт → `search_files` → `read_file_excerpts` → оригинал при необходимости.
`read_file_bytes` отдаёт base64 частями до 256 КиБ. Не загружай все файлы/граф в контекст агента.
Поиск текста использует текущие ревизии сообщений и исключает явно `obsolete`/`superseded`
наблюдения. Для исторического вопроса `list_files(include_history=true)` и `read_file` сохраняют
все версии. Дата, роль сообщения и статус файла важнее числа графовых соседей.

Входные страницы и паспорта экспортируются в Markdown. Ручные изменения сохраняются;
обновлённая проекция появляется рядом как `.incoming.md`, конфликт возвращается инструментом.
`refresh_vault` повторно строит страницы из базы после прерывания. Не удаляй правки человека ради
«чистого» отчёта. Автоматическая миграция старой памяти создаёт каталоги, но не восстанавливает
утраченные файлы или неизвестное назначение: такие пробелы остаются видимыми.
