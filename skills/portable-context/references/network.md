# VPN и сеть: Windows, macOS, Linux

Чат может использовать VPN, а соединение с памятью — обычную сеть. Не отключай VPN целиком.
Помощник `deploy/network.py` использует стандартную библиотеку Python 3.11+ и системные средства:
NetTCPIP PowerShell в Windows, `route`/`netstat` в macOS, `iproute2` в Linux.
Он не передаёт историю, не читает облачные ключи, не меняет firewall и не создаёт облачных ресурсов.

## Сценарий агента

1. Используй существующий `PRIVATE_STATE` с `deployment.json`, абсолютный путь вне репозитория.
   Не заводи вторую установку. Выбери доступный Python: `python` в Windows, `python3` либо Python
   виртуального окружения в macOS/Linux. Все приведённые ниже команды имеют одинаковые аргументы.
2. Выполни `inspect`. Если соединение работает, не добавляй исключения только из-за наличия VPN.
   Различай TCP-доступность, успешную TLS-аутентификацию API и полноценный вызов MCP.
3. Если нужен прямой доступ, подготовь `plan`. При одном подходящем шлюзе он выбирается автоматически.
   При нескольких сопоставь интерфейсы с реальной Wi-Fi/Ethernet-сетью пользователя и выбери явно.
   Не копируй шлюз, IP или номер интерфейса из другой установки.
4. Покажи конкретные адреса и удаления старых собственных маршрутов из плана. Применение требует
   администратора Windows либо `sudo` в macOS/Linux. Это изменение сети на компьютере пользователя;
   используй уже данное разрешение на соответствующий сценарий, системный запрос повышения прав
   человек подтверждает сам. Не проси пароль администратора в чате.
5. Повтори `inspect`, затем `setup.py ... check`. Если TCP работает, а SSH нет — проверь ключ,
   разрешённый облачным firewall адрес выхода и совместимость клиента. Не открывай SSH всему интернету.

```sh
python deploy/network.py --state PRIVATE_STATE inspect --scope all
python deploy/network.py --state PRIVATE_STATE plan --scope all
python deploy/network.py --state PRIVATE_STATE apply --approve-plan PLAN_SHA256
python deploy/setup.py --state PRIVATE_STATE check
```

До создания ВМ используй `--scope cloud`. После установки обычно достаточно `--scope server`.
`all` включает API и ВМ. План показывает, какие ранее созданные помощником исключения будут убраны
при смене охвата. Для своего сервера без cloud.ru доступны серверные исключения.
Если выбор неоднозначен: `plan --scope server --interface INTERFACE --gateway GATEWAY`.
Windows использует номер интерфейса, macOS/Linux — имя (`en0`, `eth0` и т. п.).

В Windows агент готовит одну строку для уже открытого PowerShell от имени администратора.
В macOS/Linux повышается только команда применения, например:
`sudo /absolute/path/to/python3 /absolute/path/to/deploy/network.py --state /absolute/private/state apply --approve-plan HASH`.
Планирование и диагностику запускай от обычного пользователя. Файлы состояния после `sudo` сохраняют
владельца приватной папки. Не запускай весь установщик, импорт или MCP под root ради маршрутов.

## Перезапуск, новая сеть, удаление

Желаемая конфигурация и журнал владения хранятся на диске; системные маршруты создаются на текущую
сессию. После перезапуска компьютера, смены Wi-Fi, шлюза или DNS агент запускает `repair`:

```sh
python deploy/network.py --state PRIVATE_STATE repair --scope server
python deploy/network.py --state PRIVATE_STATE apply --approve-plan NEW_PLAN_SHA256
```

`repair` создаёт свежий план, а не применяет устаревший шлюз. Повторный запуск не дублирует маршруты.
Старый план истекает через 10 минут; изменение DNS, сети или конфигурации требует нового плана.
Для удаления исключений: `python deploy/network.py --state PRIVATE_STATE remove` с повышенными правами.
Удаляются только записанные в журнале маршруты помощника. Совпадающие предсуществующие маршруты
используются без присвоения владения и не удаляются. При внешнем изменении маршрута работа останавливается.

При частичном сбое успешные изменения остаются в журнале, поэтому можно продолжить или удалить их.
`pending` означает прерывание в момент изменения: сначала сравни журнал с таблицей маршрутов;
не присваивай спорный маршрут помощнику автоматически. `network.lock` после аварии удаляют только
после проверки, что другой процесс помощника больше не работает.

Эта версия не устанавливает фоновую привилегированную службу или автозапуск. Проверка/восстановление
выполняются по команде агента; после перезапуска может снова понадобиться системное повышение прав.
Не обещай пользователю автоматическое восстановление без участия ОС.

## Границы

- Исключения относятся к точным IPv4-адресам `/32`, но действуют для всех приложений, обращающихся
  к этим IP. Помощник не переключает IPv6, DNS, системный прокси или маршрут по умолчанию.
- На Linux VPN с policy routing, а на любой ОС kill switch или корпоративные ограничения могут
  блокировать прямой доступ даже с маршрутом. Диагностика не объявляет успех по одному факту создания
  маршрута. В таких случаях нужен поддерживаемый режим исключений самого VPN; не снимай его защиты сам.
- Прямое соединение использует IP провайдера пользователя. Российский IP не гарантируется;
  находящемуся за границей пользователю нужен собственный российский выход.
- При смене внешнего IP разрешение SSH в cloud.ru может потребовать обновления. Помощник не хранит
  административный ключ для фонового изменения облачного firewall. Агент проводит обычный configure/plan/apply.
- macOS с несколькими физическими интерфейсами с одинаковым шлюзом требует явной настройки VPN:
  помощник не угадывает нужный интерфейс для такого маршрута.

Технические основания: [Windows NetTCPIP](https://learn.microsoft.com/en-us/powershell/module/nettcpip/new-netroute),
[Apple route](https://github.com/apple-oss-distributions/network_cmds/blob/main/route.tproj/route.8),
[Linux ip-route](https://man7.org/linux/man-pages/man8/ip-route.8.html).
