# Подключить агента к существующей памяти

Для первого запуска начни с [onboarding.md](onboarding.md). Возьми endpoint и workspace ID
из приватной памятки/проверенного состояния установки. Не создавай новую память из-за ошибки
сети или входа. Сохрани остальные MCP-подключения приложения. Проверь его текущие возможности
и формат настроек, прежде чем редактировать конфигурацию.

## HTTPS и OAuth: основной путь Cloud.ru preview

`client-https.json` из установщика описывает подключение, но не является готовым конфигом
для всех приложений. Адрес имеет вид `https://ВАШ-АДРЕС.containerapps.ru/mcp`.
Браузерный вход владельца и разрешение доступа приложению — два отдельных шага:

1. При первом запуске владелец открывает приватный файл, указанный `owner-login`, переходит
   по `login_url`, вводит код и создаёт passkey. Код в чат не передаётся. Если истёк —
   `python deploy/setup.py --state PRIVATE_STATE owner-login` выдаёт новый локальный файл.
2. Агент добавляет MCP в приложение; пользователь входит своим passkey и разрешает нужные права.
   Токены хранит приложение, не репозиторий и не приватная памятка установки.
3. Из этого приложения вызови `memory_status`, сверь workspace ID и прочитай `list_projects`.
   Успешный `https-check` установщика не заменяет проверку входа самого приложения.

Управляемая установка создаёт публичный PKCE-клиент `portable-context-desktop` без client secret.
Его разрешённый callback — **ровно** `http://127.0.0.1:14881/callback`.
Права: `openid`, `offline_access`, `memory:read`, для записи также `memory:write`.
Обычному агенту не нужны `memory:admin` или ключи облака/S3. Не повышай права из-за ошибки записи.
Сначала проверь согласие пользователя и scopes текущего токена.

### Codex: проверенный пилот

Нативный браузерный вход и чтение/запись проверены в личном пилоте; это не сертификация
всех версий приложения или массовой передачи файлов. В конфигурации Codex:

```toml
[mcp_servers.portable_context_https]
url = "https://YOUR-ORIGIN/mcp"
scopes = ["openid", "offline_access", "memory:read", "memory:write"]
startup_timeout_sec = 60
tool_timeout_sec = 180

[mcp_servers.portable_context_https.oauth]
client_id = "portable-context-desktop"
callback_port = 14881
callback_url = "http://127.0.0.1:14881/callback"
```

Затем `codex mcp login portable_context_https`. Если имя подключения другое, подставь его.
Используй настройки той версии Codex, которая установлена; при занятом порте выясни причину,
а не меняй callback только на стороне клиента. [Официальная документация MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
проверена 11 ноября 2026. После изменения конфигурации переподключи MCP в текущем приложении.

### Claude, Gemini и другие агенты

Скилл общий, настройки подключения зависят от приложения. Не копируй Codex TOML в другой клиент.

| Возможность клиента | Путь и границы проверки |
|---|---|
| HTTPS MCP с указанным client ID, PKCE и точным callback | Настроить штатно и проверить реальный browser flow, чтение и запись |
| MCP stdio и локальный SSH | Использовать `client-config.json`; это рабочая альтернатива HTTPS, вход в конкретном хосте тоже проверить |
| Требует автоматическую регистрацию OAuth | По умолчанию DCR/CIMD не включены; нужен отдельный совместимый клиент/настройка владельца |
| Только веб-чат без терминала/настройки MCP | Объяснить недостающий шаг и продолжить установку в подходящем агенте |

Нативный HTTPS для Claude Code, Hermes, OpenClaw, Ouroboros и Gemini здесь не объявлен
проверенным только на основании поддержки MCP. Не обходи ошибку регистрации wildcard callback
или открытой регистрацией. Владелец может настроить отдельный public client с точным callback;
административные детали — `docs/oauth-preview.md` в полном checkout той же версии.
Если независимый отзыв каждого устройства необходим, нужны отдельные client IDs:
общий desktop ID означает общий отзыв разрешения приложения, даже при разных токенах.

## SSH/stdio или локальная память

Возьми `command` и `args` из PRIVATE_STATE/client-config.json и перенеси в **штатный формат**
MCP текущего хоста. Не заменяй адрес сервера локальным путём. SSH-ключ остаётся у владельца;
проверяй host key и реальный вызов MCP. Для локальной памяти используй уже существующий
`--home`; пошаговый новый локальный запуск — [storage.md](storage.md).

CLI массовой отправки пока работает через stdio, включая SSH; HTTPS/OAuth-профиля у него нет.
Для него из полного checkout выполни:

```text
python deploy/client_setup.py --directory PRIVATE_CLIENT --config PRIVATE_STATE/client-config.json
```

Команда установит окружение, проверит существующую память и сохранит привязанный к ней профиль.
Если нужен только локальный разбор данных, можно опустить `--config`: это **подготовка клиента**,
подключение ещё не проверено. `client-https.json` не подставляется вместо stdio-конфига.
В дальнейших командах используй возвращённый абсолютный путь Python. Доставка через нативные
HTTPS MCP tools описана отдельно в [client.md](client.md).

## Когда подключение действительно готово

Проверь правильный workspace ID и чтение проектов. Для согласованного первого импорта сохрани
выбранный реальный материал, прочитай его обратно и проверь receipts файлов. При read-only
доступе сообщи только о проверенном чтении. Не создавай выдуманные разговоры ради теста.
Второй агент использует тот же endpoint, свой вход и тот же workspace ID; OAuth-токены
первого агента не копируются. Памятка с путями и результатами остаётся приватной.
