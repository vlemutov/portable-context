# Подключить агента к существующей памяти

Для первого запуска начни с [onboarding.md](onboarding.md). Возьми endpoint и workspace ID
из приватной памятки/проверенного состояния установки. Не создавай новую память из-за ошибки
сети или входа. Сохрани остальные MCP-подключения приложения. Проверь его текущие возможности
и формат настроек, прежде чем редактировать конфигурацию.

## HTTPS и OAuth: основной путь Cloud.ru preview

`client-https.json` из установщика описывает подключение, но не является готовым конфигом
для всех приложений. Адрес имеет вид `https://ВАШ-АДРЕС.containerapps.ru/mcp`.
Браузерный вход владельца и разрешение доступа приложению — два отдельных шага:

1. При первом запуске владелец открывает приватный файл, указанный `owner-login`, переходит
   по `login_url`, вводит код и создаёт passkey. Код в чат не передаётся. Если истёк —
   `python deploy/setup.py --state PRIVATE_STATE owner-login` выдаёт новый локальный файл.
2. Агент добавляет MCP в приложение; пользователь входит своим passkey и разрешает нужные права.
   Токены хранит приложение, не репозиторий и не приватная памятка установки.
3. Из этого приложения вызови `memory_status`, сверь workspace ID и прочитай `list_projects`.
   Успешный `https-check` установщика не заменяет проверку входа самого приложения.

Управляемая установка создаёт публичный PKCE-клиент `portable-context-desktop` без client secret.
Новые установки регистрируют точные адреса возврата для Codex (`http://127.0.0.1:14881/callback`),
Claude Code (`http://localhost:14881/callback`), Cursor Desktop (`http://localhost:8787/callback`)
и Cursor Cloud Agents (`https://www.cursor.com/agents/mcp/oauth/callback`).
Адрес в запросе входа должен точно совпасть с зарегистрированным.
Права: `openid`, `offline_access`, `memory:read`, для записи также `memory:write`.
Обычному агенту не нужны `memory:admin` или ключи облака/S3. Не повышай права из-за ошибки записи.
Сначала проверь согласие пользователя и scopes текущего токена.

### Второй passkey для входа с другого компьютера

Если первый ключ сохранён в Windows Hello, QR-код **входа** на другом компьютере
попросит телефон предъявить ключ этой памяти. Если телефон сообщает, что ключей нет,
предложи добавить второй passkey к существующей учётной записи:

1. На компьютере с рабочим ключом открыть `/settings/account` на проверенном HTTPS-адресе
   своей памяти, войти через Windows Hello и выбрать **Passkeys → Add passkey**.
2. В диалоге сохранения выбрать другой способ и затем телефон. Включить Bluetooth на обоих
   устройствах, отсканировать телефоном QR-код **создания ключа** и подтвердить сохранение.
   Проверить, что в аккаунте видны оба ключа.
3. На втором компьютере заново открыть вход из клиента в системном браузере. С включённым
   Bluetooth выбрать телефон, отсканировать свежий QR-код **входа** и подтвердить запрос.
   Из клиента вызвать `memory_status`, сверить workspace ID и прочитать известную запись.

Этот путь предполагает доступ к первому ключу. При утрате всех ключей используй
[восстановление доступа владельца](../../../docs/oauth-recovery.md).

### Codex: проверенный пилот

Нативный браузерный вход и чтение/запись проверены в личном пилоте; это не сертификация
всех версий приложения или массовой передачи файлов. В конфигурации Codex:

```toml
[mcp_servers.portable_context_https]
url = "https://YOUR-ORIGIN/mcp"
scopes = ["openid", "offline_access", "memory:read", "memory:write"]
startup_timeout_sec = 60
tool_timeout_sec = 180

[mcp_servers.portable_context_https.oauth]
client_id = "portable-context-desktop"
callback_port = 14881
callback_url = "http://127.0.0.1:14881/callback"
```

Затем `codex mcp login portable_context_https`. Если имя подключения другое, подставь его.
Используй настройки той версии Codex, которая установлена; при занятом порте выясни причину,
а не меняй callback только на стороне клиента. [Официальная документация MCP в Codex](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)
проверена 11 ноября 2026. После изменения конфигурации переподключи MCP в текущем приложении.

### Claude Code: localhost и обновление существующей установки

Claude Code использует `http://localhost:PORT/callback`; `--callback-port` фиксирует порт,
но не заменяет hostname на 127.0.0.1. [Официальная инструкция](https://code.claude.com/docs/en/mcp#use-pre-configured-oauth-credentials)
проверена 11 ноября 2026. На 2.1.321 в пользовательском пилоте зафиксирован именно localhost.
Не редактируй URL авторизации вручную: при обмене кода redirect_uri тоже должен совпадать.

Если сервер установлен до этой правки и разрешает только Codex callback, агент владельца
может исправить это через уже доступный HTTPS веб-интерфейс Pocket ID: войти существующим
passkey → Administration → OIDC Clients → Portable Context desktop → General → Add callback URL.
Добавить ровно `http://localhost:14881/callback`, сохранив `http://127.0.0.1:14881/callback`,
нажать Save и проверить подтверждение. Не менять PKCE, consent, scopes и сроки токенов.
Веб-правка не создаёт дополнительный restic checkpoint; не объявляй его выполненным.

Если нужен автоматизированный путь с резервной копией и есть административный SSH,
из нового полного checkout с прежним приватным state:

```text
python deploy/setup.py --state PRIVATE_STATE oauth-client --client claude-code
```

Команда проверяет память/issuer и принадлежность клиента, делает копию OAuth в уже настроенный
restic, затем добавляет **только** localhost callback. Сохраняет Codex callback, остальные
настройки, группы, сроки токенов и права; не создаёт нового владельца и не требует перезапуска MCP.
Повтор безопасен. Для этой правки при недоступном SSH можно использовать веб-путь выше.
Диагностика SSH, если нужна для других административных задач, — [network.md](network.md).
Повседневное HTTPS-подключение агента не требует SSH. Ошибка копии останавливает CLI-изменение.
Receipt — PRIVATE_STATE/claude-code-client.json. Обновление одного скилла эту миграцию не выполняет.

Для **нового** подключения Claude Code (URL заменить своим):

```text
claude mcp add --transport http --scope user --client-id portable-context-desktop --callback-port 14881 portable-context https://YOUR-ORIGIN/mcp
```

Если запись уже есть, сохрани её и обнови только нужные поля в её текущей области настроек;
повторный add с тем же именем завершается ошибкой. Не удаляй чужие подключения. Форма JSON:

```json
{
  "type": "http",
  "url": "https://YOUR-ORIGIN/mcp",
  "oauth": {
    "clientId": "portable-context-desktop",
    "callbackPort": 14881,
    "scopes": "openid offline_access memory:read memory:write"
  }
}
```

Для public client не нужен `--client-secret`. Попроси `/mcp` → Authenticate либо
`claude mcp login portable-context`; пользователь проходит браузерный вход. После исправления
callback запусти **новую** попытку авторизации, затем вызови memory_status и прочитай проект.
Пока этого не произошло, сообщай «callback подготовлен», а не «Claude подключён».
Desktop Chat/Cowork и Claude Code — разные клиенты, эту настройку нельзя автоматически считать
подходящей всем интерфейсам Claude. Не называй рабочее подключение другого приложения SSH,
не проверив его фактический конфиг.

**Результат пилота 11 ноября 2026:** владелец подтвердил вход Claude Code 2.1.321 по HTTPS/OAuth
через VPN без SSH/обходного маршрута; тот же workspace и существующие проекты доступны.
Выданы openid, offline_access, memory:read и memory:write без memory:admin. Это подтверждение
входа и чтения; запись, capture с файлами, refresh и отзыв именно в Claude Code ещё требуют
отдельных проверок. Codex HTTPS/OAuth после изменения callback также ответил memory_status.

Если `claude mcp get` до входа пишет `timed out`, не делай вывод, что память выключена.
Такое сообщение наблюдалось в пилоте без завершённой авторизации. Проверь URL/transport,
доступность HTTPS и OAuth metadata; ожидаемый 401 без токена означает необходимость входа,
а не успешное подключение. Запусти `/mcp` → Authenticate или `claude mcp login`, затем проверь
настоящий memory_status. Если после входа тайм-аут остаётся, это отдельная диагностика;
не скрывай его под универсальным «нужна авторизация». Текст upstream CLI мы не меняем.

### Gemini и другие агенты

Скилл общий, настройки подключения зависят от приложения. Не копируй Codex TOML в другой клиент.

| Возможность клиента | Путь и границы проверки |
|---|---|
| HTTPS MCP с указанным client ID, PKCE и точным callback | Настроить штатно и проверить реальный browser flow, чтение и запись |
| MCP stdio и локальный SSH | Использовать `client-config.json`; это рабочая альтернатива HTTPS, вход в конкретном хосте тоже проверить |
| Требует автоматическую регистрацию OAuth | По умолчанию DCR/CIMD не включены; нужен отдельный совместимый клиент/настройка владельца |
| Только веб-чат без терминала/настройки MCP | Объяснить недостающий шаг и продолжить установку в подходящем агенте |

Полный сценарий импорта/записи через Claude Code остаётся отдельной проверкой после входа.
Для Hermes, OpenClaw, Ouroboros и Gemini нативный HTTPS не объявлен
проверенным только на основании поддержки MCP. Не обходи ошибку регистрации wildcard callback
или открытой регистрацией. Владелец может настроить отдельный public client с точным callback;
административные детали — `docs/oauth-preview.md` в полном checkout той же версии.
Если независимый отзыв каждого устройства необходим, нужны отдельные client IDs:
общий desktop ID означает общий отзыв разрешения приложения, даже при разных токенах.

## Cursor Desktop — экспериментальный чистый тест

В пилоте Cloud.ru владелец подтвердил вход из Cursor на Ubuntu и чтение вики действующей
памяти после ручной регистрации адреса возврата. Для новой установки проверь регистрацию
установщиком и запиши версию Cursor и ОС. По [официальной документации Cursor](https://prod.cursor.com/docs/mcp)
статический OAuth задаётся через `auth.CLIENT_ID`; desktop callback —
`http://localhost:8787/callback`. Сверь контракт с установленной версией до настройки.

Для первого входа владельца открой ссылку из приватного файла в **системном браузере**
компьютера. Объясни заранее: после ввода кода появится запрос браузера или менеджера
ключей; пользователь выбирает доступный способ (например, телефон или FIDO2-ключ).
В пилоте на Ubuntu встроенный браузер Cursor отменил запрос без видимого системного
диалога. Если окно не появилось, повтори в обычном браузере. Если одноразовый код
истёк или отвергается, выпусти новый командой `owner-login` с тем же `--state` и
используй новый приватный файл; срок кода — 20 минут. Действующий passkey используй
повторно. Код, ссылку с кодом и содержимое recovery kit в чат не передавай.

Новая установка регистрирует desktop callback Cursor при создании OAuth-клиента.
На прежней установке сначала проверь существующее подключение. Если нужна миграция,
используй `python deploy/setup.py --state PRIVATE_STATE oauth-client --client cursor`
из актуального checkout. Команда сверяет workspace и issuer, перед изменением делает
резервную копию OAuth, сохраняет настройки владельца и проверяет результат. Повторный
запуск безопасен. Для конфигурации Cursor доступен `client-cursor.json` в этой папке.
Объедини его запись с существующей конфигурацией Cursor, сохрани другие подключения.

В отдельной папке теста используй `.cursor/mcp.json` (или настройку текущей версии Cursor).
Пример после замены URL на `mcp_url` из новой HTTPS receipt:

```json
{
  "mcpServers": {
    "portable-context-test": {
      "url": "https://NEW-MEMORY-ORIGIN/mcp",
      "auth": {
        "CLIENT_ID": "portable-context-desktop",
        "scopes": ["openid", "offline_access", "memory:read", "memory:write"]
      }
    }
  }
}
```

Выполни настоящий browser login и вызов memory_status из Cursor, сравни workspace_id с receipt.
При ошибке не заменяй HTTPS на SSH незаметно: запись об успехе HTTPS требует этого транспорта.
Для первого импорта спроси, какой диалог или фрагмент сохранить и какие вложения включить.
Нативного адаптера истории Cursor в этой версии нет. Используй доступный локальный экспорт
или выбранную переписку, сохраняя роли, стабильные идентификаторы и только известные связи;
служебные вставки и вызовы инструментов учитывай отдельно от реплик пользователя.
До отправки покажи состав, число записей и файлов. Если источник недоступен, попроси экспорт.

Назови способ доставки **до установки локального клиента**. При наличии HTTPS MCP с правом
записи и доступом к выбранным данным отправь записи через `stage_records`/`run_import`
или пакет через штатные capture upload tools. Для CLI `send` объясни: «Вход с passkey уже
работает. Для доставки этого пакета клиент использует существующий SSH-профиль установки».
Проверь совпадение workspace ID у выбранного транспорта. При отсутствии подходящего SSH
предложи HTTPS-путь с учётом возможностей клиента. [Команды подготовки и доставки](client.md).

Покажи результат по квитанции завершённого импорта и чтению выбранного сообщения обратно
из Cursor. Если выбран файл, проверь его сохранение. При проверке повторной отправки возьми
тот же пакет и сверь счётчики добавленных и изменённых записей. При прерывании назови
оставшийся шаг, сохрани ID пакета/задания и продолжай его.

## Cursor Cloud Agents

Если диалог перенесён в Projects и выполняется облачным агентом, подключи MCP через
[панель плагинов Cursor](https://cursor.com/dashboard/plugins). Файл `client-cursor.json`
и запись в `.cursor/mcp.json` выше относятся к редактору с адресом возврата
`http://localhost:8787/callback`. Облачный агент использует
`https://www.cursor.com/agents/mcp/oauth/callback` с обязательным `www`.

Для прежней памяти из обновлённого checkout выполни
`python deploy/setup.py --state PRIVATE_STATE oauth-client --client cursor` с папкой этой установки.
Команда добавляет недостающие адреса после резервной копии OAuth. В новой установке оба уже зарегистрированы.

В панели выбери **Add New MCP server → Edit JSON**. Замени весь шаблон с `my-server`
следующим блоком. Подставь свой полный HTTPS-адрес памяти вместо `https://EXAMPLE/mcp`.
У публичного клиента PKCE нет секрета. В форме нет отдельного поля для областей доступа:
без явного списка Cursor может запросить только `openid`, `profile`, `email`, `groups`,
`offline_access`. Для чтения и записи памяти нужны права из блока.

```json
{
  "portable-context-cloudru": {
    "url": "https://EXAMPLE/mcp",
    "auth": {
      "CLIENT_ID": "portable-context-desktop",
      "scopes": ["openid", "offline_access", "memory:read", "memory:write"]
    }
  }
}
```

Сохрани, запусти новый вход и подтверди запрошенные права. Из облачного агента вызови
`memory_status`, сверь workspace ID и открой знакомую страницу; в редакторе проверь свой вход отдельно.

## Claude Cowork

Владелец добавляет удалённый сервер через **Customize → Connectors → Add → Custom connector**.
В организационном пространстве для добавления может требоваться владелец или администратор.
Введи название и публичный HTTPS URL своей памяти вместе с `/mcp`. Выбери вход через OAuth
и **Use your own OAuth client**. Укажи `portable-context-desktop`, оставь секрет пустым.
Включи подключение в Cowork. [Инструкция Anthropic](https://support.claude.com/en/articles/11175166-get-started-with-custom-connectors-using-remote-mcp)

Новая установка сразу регистрирует `https://claude.ai/api/mcp/auth_callback`.
Для действующей памяти выполни `python deploy/setup.py --state PRIVATE_STATE oauth-client --client claude-cowork`.
Войди через passkey, вызови `memory_status` из Cowork и сверь workspace и права.
Для чтения нужна `memory:read`, для импорта — `memory:write`. Прочитай знакомую страницу.
Если прав на запись нет, зафиксируй это до первого импорта.

## SSH/stdio или локальная память

Возьми `command` и `args` из PRIVATE_STATE/client-config.json и перенеси в **штатный формат**
MCP текущего хоста. Не заменяй адрес сервера локальным путём. SSH-ключ остаётся у владельца;
проверяй host key и реальный вызов MCP. Для локальной памяти используй уже существующий
`--home`; пошаговый новый локальный запуск — [storage.md](storage.md).

CLI массовой отправки пока работает через stdio, включая SSH; HTTPS/OAuth-профиля у него нет.
Для него из полного checkout выполни:

```text
python deploy/client_setup.py --directory PRIVATE_CLIENT --config PRIVATE_STATE/client-config.json
```

Команда установит окружение, проверит существующую память и сохранит привязанный к ней профиль.
Если нужен только локальный разбор данных, можно опустить `--config`: это **подготовка клиента**,
подключение ещё не проверено. `client-https.json` не подставляется вместо stdio-конфига.
В дальнейших командах используй возвращённый абсолютный путь Python. Доставка через нативные
HTTPS MCP tools описана отдельно в [client.md](client.md).

## Когда подключение действительно готово

Проверь правильный workspace ID и чтение проектов. Для согласованного первого импорта сохрани
выбранный реальный материал, прочитай его обратно и проверь receipts файлов. При read-only
доступе сообщи только о проверенном чтении. Не создавай выдуманные разговоры ради теста.
Второй агент использует тот же endpoint, свой вход и тот же workspace ID; OAuth-токены
первого агента не копируются. Памятка с путями и результатами остаётся приватной.
