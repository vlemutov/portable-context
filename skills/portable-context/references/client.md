# Клиент 0.6: импорт с компьютера пользователя

Перед новой выгрузкой прочитай [controls.md](controls.md): правила отбора, категории файлов,
группы, журнал и обработка перенесённых сессий. Клиент 0.6 требует сервер с возможностями 0.6;
сначала обнови сервер, затем клиент и установленный скилл. Настройки SSH/stdio сохраняются.

`prepare` и `send` принимают `--policy PATH`, `--include-path PATH` (повторяемый) и `--agent NAME`.
Без `--policy` используется `PC_CAPTURE_POLICY` либо существующий `~/.portable-context/capture-policy.json`.
Неизвестный или некорректный файл правил не игнорируется. `--include-path` разрешает конкретный
служебный файл, но не отменяет правила проекта и не добавляет разрешённый корень файловой системы.
`discover` показывает все native-сессии внутри файла; `--session` выбирает только указанную сессию.
Новые события продолжающегося диалога при следующей сборке ожидаемы; старые записи не должны меняться
из-за времени выгрузки или переименования диалога. Для сохранения исполнителя укажи известное имя
агента, например `--agent Claude-Code`; это заявленная метка, не проверка личности.

Используй 0.5.1 или новее. Для пакета, собранного в 0.5.0, сначала выполни одной строкой
`python -m portable_context.client upgrade-capture --package OLD --destination NEW`, затем отправь NEW.
Это исправляет объединение паспортов инструментальных результатов разных сообщений, сохраняя
исходные ID сообщений и уже захваченные байты. Старый пакет и исторические версии остаются доступны.

Пользователь выбирает диалоги обычными словами. Агент находит их локально, уточняет неоднозначный
выбор и выполняет команды. MCP сам по себе не получает доступ к истории клиента.

## Установка и подключение

Нужны Python 3.11+ и терминал. Из проверенного checkout Portable Context запусти одной строкой:

```text
python deploy/client_setup.py --directory /private/portable-context-client --config /private/client-config.json
```

Команда работает на Windows, macOS и Linux: создаёт отдельное окружение, устанавливает клиент с
MCP и проверяет существующую память. JSON-конфигурация содержит `mcpServers.portable-context`
с `command`/`args` существующего stdio-подключения (локальный процесс или SSH). При первой
установке сервера её выдаёт `deploy/setup.py install`. Если подключения ещё нет, сначала
следуй deployment.md. Пути примеров заменяй реальными; не проси секреты в чат.

Используй путь `python`, возвращённый установщиком, во всех командах ниже. Профиль привязан к
workspace_id: другой сервер с другой памятью не принимается незаметно. Здесь реализован stdio,
включая SSH; прямой HTTP-клиент/OAuth не включён. Ключи S3 остаются только на сервере.

## Выбор и подготовка

```text
python -m portable_context.client discover --instance my-claude-computer
```

По умолчанию ищет `$CLAUDE_CONFIG_DIR/projects` либо `~/.claude/projects`. `--root` позволяет
задать иной каталог или конкретный JSONL. Показывай человеку названия и число записей, а не UUID.
Выбранные ID подставь в команду; повторяй `--session` для нескольких диалогов:

```text
python -m portable_context.client prepare --instance my-claude-computer --session SESSION_ID --destination /private/capture-001 --source-root /private/chosen-project
```

`--all` используется только при выборе всех найденных сессий пользователем. Субагенты показываются
отдельно и включаются явно. Имя instance сохраняй между выгрузками. Для перенесённых копий адаптер
объединяет совпадающие native UUID; при противоречии требует выбрать конкретный файл через `--root`.
Не выбирай копию только по дате изменения. Незавершённая последняя JSONL-строка откладывается.
Неизвестные типы сохраняются как служебные данные и перечисляются в отчёте, без угадывания смысла.

Для официального архива claude.ai добавь `--format claude-web --root /private/export.zip` к discover
и prepare. Выбор производится на компьютере; полный архив не отправляется. Вложения, для которых
экспорт не дал доступного локального пути, останутся явно недоступными.

По умолчанию проверка секретов блокирует сборку при совпадении. Можно выбрать `--secrets redact`:
известные совпадения в структурированном тексте заменяются пометками, подозрительные файлы и
бинарные payload не отправляются. Оригинальные сессии не изменяются. Персональные данные не
обезличиваются автоматически: помоги пользователю исключить ненужные диалоги/файлы до сборки.
Это эвристическая проверка, не гарантия отсутствия всех секретов. Нечитаемые/бинарные файлы имеют
явное состояние opaque/partial; объясни это при необходимости до передачи.

Доступные thinking-блоки по умолчанию исключены с подсчётом объёма; `--thinking archive` сохраняет
их отдельными объектами без включения в обычный поиск. Никакие скрытые данные не восстанавливаются.
Инструментальные вызовы/результаты сохраняются как отдельные payload, включая ID вызова.
Файлы Read/Write/Edit — ссылки на доступные сейчас байты; историческая версия файла из этого не следует.
Упоминание пути не даёт разрешение копировать диск. Выбирай узкие корни или точные разрешённые файлы.

## Доставка и проверка

```text
python -m portable_context.client send --profile /private/portable-context-client/profile.json --package /private/capture-001
```

Для назначения существующему проекту добавь `--project-id CATALOG_PROJECT_ID`. Новый пустой проект
можно создать через MCP `create_project`; временный диалог для этого не нужен.

Клиент проверяет версию протокола и workspace_id, передаёт только отсутствующие части, сверяет
контрольные суммы и импортирует файлы ограниченными порциями. При обрыве повтори ту же команду
с тем же пакетом. Следующую выгрузку создай в новой папке: неизменённые записи не получают новые
версии из-за времени сборки. В этой версии нет автоматически запущенного фонового наблюдения.

Результат и `last-delivery.json` различают доставку, доступность файлов, S3 и ограничения полноты.
Проверяй `complete`, `missing_at_capture`, `completeness`, `s3`. Даже `complete=true` подтверждает
импорт выбранного пакета, а не полноту исходного аккаунта. `list_capture_receipts` возвращает
отчёты с другого клиента. `check_memory` — сводка, фильтр issue_type и страницы offset/limit.
Сначала показывай человеку итог и причины пропусков, затем переходи к выбранному обогащению.

Старые capture-v1 принимаются сервером напрямую через `import_file_capture`; новая MCP-доставка
использует capture-v2. Обновление сервера делается после резервной копии тем же deploy/setup.py install,
без новых облачных ресурсов. Переподключи MCP в уже открытых клиентах после обновления.
# Client additions in 0.7

Project folders are independent evidence, selected by an explicit root→project binding. Follow
[recovery-and-folders.md](recovery-and-folders.md) for `project-preferences`, `project-preview`,
`project-bind`, `project-bindings`, `project-prepare`, and normal resumable `send`.
The assistant includes approved bindings in subsequent user-requested exports; `prepare` for
conversations alone does not implicitly scan folders. Discovery exposes Claude project `memory_roots`.
Referenced temporary outputs/scripts may now be captured; privacy policy and source-root checks win.
Update the server before using folder capture; reconnect MCP after upgrading client/server/skill.
