# Timeweb: маршрут агента

Читайте этот файл только при установке или обслуживании Timeweb. Сначала определите:
новая память, подключение существующей, продолжение установки или обслуживание.
Ошибка подключения сама по себе не означает новую установку.

1. Нужен полный checkout той же версии, что и скилл. Для текущего испытания —
   `feature/timeweb-installer`; зафиксируйте полный commit и проверьте его CI.
   При наличии только копии скилла сначала получите полный репозиторий.
2. Следуйте [инструкции установки](../../../docs/timeweb-install.md). Подготовьте команды
   под ОС пользователя, Python 3.11+ и OpenSSH. Terraform/Docker клиенту не нужны.
3. Человек создаёт аккаунт, оплачивает и вводит токен в скрытом локальном запросе.
   Объясните две независимые опции: ограниченные административные права и скрытие секретов.
   Для автономного пути нужны права создания проекта и отключённое маскирование.
   Используйте кратчайший доступный срок; токен нужен контроллеру и после установки.
4. До создания ресурсов покажите тарифы, зоны, линейки CPU, стоимость всего комплекта и
   согласуйте расходы. Сначала прочитайте [биллинг](../../../docs/timeweb-billing.md):
   отличайте расход облачного баланса от списания с карты. Проверьте автопополнение;
   оно может списать месячную сумму даже при коротком тесте. Не обещайте банковский
   лимит по оценке «ставка × часы». Неизвестные настройки оплаты уточните до создания.
   После `plan` подготовьте `timeweb-payment --hours HOURS --monthly-extras EXTRAS_RUB --autopay STATUS`.
   Покажите суммы и риск пополнения. Только после согласия на показанные условия сохраните
   квитанцию через `timeweb-payment --approve-plan PAYMENT_SHA256` в той же папке.
   Предпочтения по региону/цене используйте при выборе запасного тарифа.
   Не объявляйте тариф доступным по одному каталогу. Не создавайте ВМ вручную параллельно агенту.
   Если регион есть в API, но отсутствует в панели, считайте возможность заказа
   неподтверждённой; не выбирайте его автоматически из-за низкой цены.
5. Храните private state вне checkout. После ошибки продолжайте его же. Пользователю
   сообщайте стадию и продолжающуюся оплату; не требуйте повторно известные сведения.
6. Используйте [штатные команды обслуживания](../../../docs/timeweb-operations.md):
   `timeweb-diagnostics`, `timeweb-update`, `timeweb-cleanup`. Не переписывайте journal/commit
   вручную и не пишите свой удаляющий скрипт вместо команды. `cleanup` без префикса означает
   обслуживание файлов памяти и **не** удаляет облачную установку.
7. При успехе помогите с passkey, OAuth и реальным MCP в выбранном клиенте. Затем небольшой
   выбранный импорт с файлом, чтение и повтор без дублей. Не называйте инфраструктурный
   healthcheck успешным входом Cursor. Технические ID храните в приватной памятке, человеку
   показывайте понятный итог и следующий шаг.

При смене этапа, заметном ожидании или ошибке используйте последнее событие `Timeweb progress`
или выполните `python deploy/setup.py --state PRIVATE_STATE install-status`. В нескольких фразах:
что подтверждено и чем, чего ждём, сколько стоит уже выделенное и как продолжить. Подставьте
прежний путь из `progress.same_state`. Пока команда работает, наблюдайте за её выводом;
`resume` нужен при остановке. При потере ответа сначала сверьте ресурс. Оценку удержания
берите из `progress.cost`: обозначайте известный подытог и неизвестные строки, по возможности
дополняйте их данными счёта этой установки. Будущие тарифы и автопополнение показывайте отдельно.
Если время ожидания неизвестно, назовите условие следующей проверки вместо обещания срока.

Например: «ВМ и бакет уже выделены. Ждём первый SSH-ответ от этой ВМ. По сохранённым тарифам
ВМ и S3 стоят X ₽/мес., IPv4 и трафик уточняются. Если команда завершится по тайм-ауту,
проверю доступ по SSH и продолжу `install --https` в той же папке». После успешного HTTPS
перейдите к [первому входу и импорту в Cursor](connection.md#cursor-desktop--экспериментальный-чистый-тест).
Об успехе клиентского пути сообщайте по ответу самого клиента и квитанции импорта.

При потерянном ответе создания App не сбрасывайте журнал: найдите приложение и
используйте `timeweb-reconcile`. Если повторные полные проверки ничего не нашли,
объясните риск запоздалого дубля и после согласия используйте `timeweb-retry-create`
с проверенным хэшем, затем `install --https` на той же папке состояния. Это одноразовое
разрешение на создание, отдельное от `timeweb-retry-deploy` для сборки существующего App.
Подробнее — [обслуживание](../../../docs/timeweb-operations.md).

`400 servers_is_run_out_error` при создании ВМ — отказ с неподтверждённой причиной,
не доказанная квота/верификация аккаунта. Не повторяйте `apply` и не создавайте новую
папку состояния: используйте `timeweb-vm-options` и подтверждённый `timeweb-select-vm`
по [разделу об отказах ВМ](../../../docs/timeweb-install.md). Для самостоятельного перебора
сначала согласуйте весь список через `timeweb-auto-plan` и запустите `timeweb-auto-run`:
регионы, минимальные параметры, полный месячный предел, запас на IPv4/переменные расходы,
число попыток, срок и автопополнение. Одного согласия на этот план достаточно для его
кандидатов. Для расчёта и подтверждения используйте `timeweb-payment --scope auto`.
При продолжении согласованной очереди используйте её исходный хэш.
Первую выделенную ВМ сохраняйте и продолжайте обычную установку на ней. Не называйте
каталог проверенным списком свободных серверов. Поиск не обходит неизвестные ошибки,
потерю ответа, ошибки прав/оплаты и не расширяет согласованные пределы. После остановки
новый поиск требует нового плана; пока `running` — продолжайте прежнюю команду.
Без согласованного автоматического плана после отказа другого варианта остановите перебор
и подготовьте диагностику для поддержки. Не обещайте доступность
Москвы/Петербурга по историческому успеху. Без отдельного поручения обращение не отправляйте.

Если отказ `409 no_free_node` пришёл на создание **приложения**, покажите на том же
`--state` план `timeweb-cleanup` без подтверждения и варианты `timeweb-select-app`
с ценами. При выборе тарифа согласуйте полную стоимость, затем хэш плана
`timeweb-select-app --preset-id ID`. После выбора обновите расчёт `timeweb-payment`
для нового тарифа и сохраните согласие перед заказом. Затем продолжайте
`install --https`. Порядок для старых журналов описан в [инструкции](../../../docs/timeweb-operations.md).

Для чистого теста на другом компьютере используйте
[сценарий Cursor/Timeweb](../../../docs/timeweb-clean-test.md). Старая папка установки и
контекст разработчика не нужны. Не импортируйте всю историю без выбора пользователя.
После теста удаляйте ресурсы только по согласованному плану. Согласие на создание не
разрешает уничтожение единственной копии памяти; при удалении бакета исчезнут и бэкапы.
