# Timeweb: маршрут агента

Читайте этот файл только при установке или обслуживании Timeweb. Сначала определите:
новая память, подключение существующей, продолжение установки или обслуживание.
Ошибка подключения сама по себе не означает новую установку.

1. Нужен полный checkout той же версии, что и скилл. Для текущего испытания —
   `feature/timeweb-installer`; зафиксируйте полный commit и проверьте его CI.
   При наличии только копии скилла сначала получите полный репозиторий.
2. Следуйте [инструкции установки](../../../docs/timeweb-install.md). Подготовьте команды
   под ОС пользователя, Python 3.11+ и OpenSSH. Terraform/Docker клиенту не нужны.
3. Человек создаёт аккаунт, оплачивает и вводит токен в скрытом локальном запросе.
   Объясните две независимые опции: ограниченные административные права и скрытие секретов.
   Для автономного пути нужны права создания проекта и отключённое маскирование.
   Используйте кратчайший доступный срок; токен нужен контроллеру и после установки.
4. До создания ресурсов покажите тарифы, зоны, линейки CPU, стоимость всего комплекта и
   согласуйте расходы. Предпочтения по региону/цене используйте при выборе запасного тарифа.
   Не объявляйте тариф доступным по одному каталогу. Не создавайте ВМ вручную параллельно агенту.
5. Храните private state вне checkout. После ошибки продолжайте его же. Пользователю
   сообщайте стадию и продолжающуюся оплату; не требуйте повторно известные сведения.
6. Используйте [штатные команды обслуживания](../../../docs/timeweb-operations.md):
   `timeweb-diagnostics`, `timeweb-update`, `timeweb-cleanup`. Не переписывайте journal/commit
   вручную и не пишите свой удаляющий скрипт вместо команды. `cleanup` без префикса означает
   обслуживание файлов памяти и **не** удаляет облачную установку.
7. При успехе помогите с passkey, OAuth и реальным MCP в выбранном клиенте. Затем небольшой
   выбранный импорт с файлом, чтение и повтор без дублей. Не называйте инфраструктурный
   healthcheck успешным входом Cursor. Технические ID храните в приватной памятке, человеку
   показывайте понятный итог и следующий шаг.

При потерянном ответе создания App не сбрасывайте журнал: найдите приложение и
используйте `timeweb-reconcile`. Если повторные полные проверки ничего не нашли,
объясните риск запоздалого дубля и после согласия используйте `timeweb-retry-create`
с проверенным хэшем, затем `install --https` на той же папке состояния. Это одноразовое
разрешение на создание, отдельное от `timeweb-retry-deploy` для сборки существующего App.
Подробнее — [обслуживание](../../../docs/timeweb-operations.md).

Для чистого теста на другом компьютере используйте
[сценарий Cursor/Timeweb](../../../docs/timeweb-clean-test.md). Старая папка установки и
контекст разработчика не нужны. Не импортируйте всю историю без выбора пользователя.
После теста удаляйте ресурсы только по согласованному плану. Согласие на создание не
разрешает уничтожение единственной копии памяти; при удалении бакета исчезнут и бэкапы.
