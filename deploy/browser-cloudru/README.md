# Cloud.ru из браузера · прототип

Владелец создаёт новую память из личного кабинета Cloud.ru. ГигаАгент можно использовать для подсказок и затем подключить к памяти по OAuth. Отдельный компьютер с терминалом, собственный домен и публикация в Маркетплейсе для этого сценария не требуются. Прототип предназначен для отдельного проекта с одной новой ВМ Ubuntu 24.04 AMD64.

## Попробовать бесплатно

1. Откройте [prepare.html](prepare.html) на GitHub, нажмите **Download raw file** и откройте скачанный файл в браузере на своём компьютере.
2. Для знакомства заполните поля вымышленными значениями. Нажмите **Создать пароль и зашифровать настройки**. Можно сделать это при выключенном интернете. Файл показывает пароль и готовый текст для поля Cloud.ru. Здесь можно остановиться. Ресурсы в облаке появляются только при заказе в кабинете.
3. Для реальной установки сохраните пароль в менеджере паролей. Он понадобится после перезагрузки ВМ и при восстановлении. У каждой генерации свои пароль и шаблон. Сохраните именно пару, использованную при заказе.

HTML работает локально, без внешних скриптов, отправки форм и сетевых запросов. В `cloud-init` попадёт зашифрованный блок (AES-GCM, PBKDF2-SHA256) и фиксированная Git-ревизия. Облачные ключи расшифровываются на ВМ пользователя. Пароль, одноразовый код, ключи и комплект восстановления держите вне чата и GitHub.

## Подготовить свой проект для реального прогона

Эти шаги приводят к расходам. До заказа проверьте доступность нужной зоны, квоты и стоимость ВМ, диска, IPv4, S3, Artifact Registry, Container Apps, Secret Management и трафика. Даже во время паузы уже заказанные ресурсы могут тарифицироваться. [Калькулятор Cloud.ru](https://cloud.ru/calculator)

1. Выберите отдельный проект, доступ к управлению ВМ и её виртуальной консоли оставьте только доверенным администраторам. Сохраните **ID проекта**. Создайте для ВМ выделенную группу безопасности: разрешите исходящий трафик к DNS, репозиториям Ubuntu, GitHub, PyPI, реестрам и сервисам Cloud.ru. Оставьте внешний SSH закрытым. Для первичного доступа используется экран ВМ в кабинете.
2. В **Хранение данных → Object Storage** создайте отдельный приватный бакет, включите версионирование. Убедитесь, что и ACL, и политики бакета исключают публичный доступ. На этот бакет выдайте отдельному сервисному аккаунту роли `s3e.viewer` и `s3e.editor`. Создайте ключ этого аккаунта. Для поля **S3 Access Key** соедините Tenant ID из раздела «Параметры работы с API» и Key ID через двоеточие. Key Secret введите в соседнее поле. [Бакет](https://cloud.ru/docs/s3e/ug/topics/guides__bucket-create) · [Ключ S3](https://cloud.ru/docs/s3e/ug/topics/api__api-key)
3. Создайте второй сервисный аккаунт в этом проекте и его Key ID и Key Secret. Установщику нужны чтение сетевого интерфейса, создание правила группы безопасности, создание закрытого Docker-реестра и запись образа, управление своим контейнером и его транспортными секретами. Сохраните ключ для контроллера продления mTLS на ВМ. Отзыв требует согласованной замены ключа. [Сервисные аккаунты и ключи](https://cloud.ru/docs/console_api/ug/topics/guides__api_key)
4. Заполните локальный HTML этими данными и сохраните пароль. В кабинете выберите **Инфраструктура → Виртуальные машины → Создать виртуальную машину**, Ubuntu 24.04 AMD64, загрузочный диск (ориентир 40 ГБ), от 2 ГБ RAM, один интерфейс с публичным IPv4 и выбранной группой безопасности. Включите **Скрипт cloud_init** и вставьте весь сгенерированный текст, начиная с `#cloud-config`. Сверьте стоимость перед заказом. [Форма создания ВМ](https://cloud.ru/docs/virtual-machines/ug/topics/guides__create-vm)

## Включить память и войти

1. Откройте **Виртуальная консоль** этой ВМ. После загрузки пакетов на экране появится меню **Portable Context | Cloud.ru setup**. Для выбора наберите цифру и нажмите Enter. Выберите **Unlock settings and prepare plan** и наберите сохранённый пароль. Виртуальная консоль Cloud.ru не поддерживает вставку из буфера обмена. [Виртуальная консоль](https://cloud.ru/docs/virtual-machines/ug/topics/guides__console)
2. Мастер проверяет доступ к бакету и версионирование, читает сетевой интерфейс через Terraform и сверяет ID ВМ и внутренний IPv4 с данными гостя. В пункте **Review costs and install / resume** он покажет проект, публичный IPv4, группу безопасности и имя будущего контейнера. Проверьте тарифы и квоты в своём кабинете. Для подтверждения введите пароль мастера и `YES`.
3. После подтверждения штатный установщик использует SSH внутри той же ВМ по loopback. Он устанавливает память, создаёт зашифрованные копии в S3, настраивает Pocket ID, публикует HTTPS через Container Apps и выполняет проверки восстановления и входа без токена. Сертификаты связи контейнера с ВМ обслуживает существующий контроллер. Проект, ВМ, бакет, данные и расходы остаются у владельца.
4. Выберите **Create passkey / owner sign-in**. В обычном браузере **на своём устройстве** откройте показанный HTTPS-адрес входа, введите одноразовый код и зарегистрируйте passkey. Публичное имя можно также скопировать из карточки контейнера в Cloud.ru. Код действует 20 минут. Passkey создаётся на устройстве владельца.
5. В ГигаАгенте откройте **Плагины → Добавить → MCP-сервер**. Укажите HTTPS-адрес с окончанием `/mcp`, OAuth, клиент `portable-context-desktop`, области `openid offline_access memory:read memory:write`. В поле разрешённых инструментов оставьте пустое значение для полного набора инструментов в границах этих прав. Сохраните плагин и нажмите **Авторизоваться**. После входа попросите вызвать `memory_status` и показать `workspace_id`. При первом входе новая память пуста.
6. Выберите **Export recovery kit to S3**. Мастер проверит принадлежность комплекта этой памяти, загрузит его и сверит содержимое обратным чтением. Скачайте показанный объект через кабинет S3, отдельно сохраните пароль. Для проверки скачайте [open-kit.html](open-kit.html), откройте его локально, выберите файл и введите пароль. Полученный ZIP содержит ключ S3 и пароль restic: храните его в защищённом месте. [Восстановление памяти и OAuth](../../docs/oauth-recovery.md)

## Если установка остановилась

Вернитесь в виртуальную консоль **той же ВМ**. Проверенный план и журнал хранятся в домашней папке `pcowner` в `.local/share/pc-browser-state`. Повтор использует тот же план и идентификаторы. Ошибка или закрытие окна не удаляет ресурсы. Если Cloud.ru не подтвердил создание реестра или контейнера и результат неоднозначен, остановитесь и проверьте ресурсы проекта. Штатная сверка неоднозначных операций описана в [инструкции продолжения](../../docs/install-resume.md). Графического интерфейса для такой ручной сверки в прототипе пока нет.

Проверка доступности по схеме провайдера и автономные тесты не подтверждают фактическую ёмкость зоны и точный набор IAM-ролей. Полный путь «пустой проект → реальная ВМ → ГигаАгент» требует отдельного согласованного прогона. Для тестирования используйте только синтетические данные. В этой версии мастер не удаляет инфраструктуру: после прогона проверьте по отдельности контейнер, реестр, секреты, ВМ, диск, IPv4 и бакет с версиями объектов.
