# История изменений Portable Context

## 1.0.1 · 24 ноября 2026

- Новый HTTPS-сервер регистрирует callback веб-версии ГигаАгента для публичного OAuth-клиента с PKCE. На существующей памяти используйте `oauth-client --client gigaagent` из этой версии с прежней папкой состояния. Команда сохраняет остальные callback, настройки клиента и выданные права.
- [Инструкция для ГигаАгента](skills/portable-context/references/connection.md#gigaagent) описывает разницу между правами OAuth и фильтром инструментов, а также проверку подключения по workspace ID. Владелец подтвердил вход и вызов статуса. Импорт из веб-интерфейса требует отдельной проверки.

## 1.0.0 · 23 ноября 2026

Первый стабильный выпуск. Пакет Python, сервер и скилл имеют версию `1.0.0`. Установщик и скилл берите из тега `v1.0.0`.

На Cloud.ru обновление действующей памяти с 0.9.0 до RC.1 сохранило вход Cursor. Cursor на Ubuntu и Codex на Windows независимо скачали прежний файл, сверили SHA-256 и прочитали прежнюю версию вики. Между RC.1 и стабильной версией обновились номера версий и документация. [Результаты приёмки](docs/release-1.0.md#cloudru-upgrade-to-rc1)

### Что изменилось с 0.9

- **Доступ к своей памяти по HTTPS.** У Cloud.ru и Timeweb вход работает на техническом домене провайдера. SQLite, вики и OAuth остаются на постоянном диске ВМ. Владелец входит с passkey и выдаёт каждому клиенту права на чтение или запись. SSH остаётся доступным для администрирования и массового переноса.
- **Установка и продолжение с того же места.** Для Cloud.ru установщик проверяет сеть и квоты, готовит план затрат и помогает диагностировать SSH при включённом VPN. Для Timeweb он учитывает подтверждённые цены, условия автоплатежа, доступность конфигураций и ожидание DNS. Обе установки сохраняют состояние, необходимое для повторной попытки. [Cloud.ru](skills/portable-context/references/deployment.md) · [Timeweb](docs/timeweb-install.md)
- **Восстановление доступа.** К резервной копии памяти с оригиналами добавлены отдельная зашифрованная копия OAuth и комплект восстановления у владельца. После потери установки восстанавливается прежний workspace, а владелец регистрирует новый passkey и заново разрешает доступ клиентам. [Процедура восстановления](docs/oauth-recovery.md)
- **Подключение разных агентов.** Для Codex проверены HTTPS, чтение и запись, обновление токена, отзыв и повторный вход. Для Cursor Desktop проверены установка с Ubuntu и импорт с повтором без дублей. Claude Code имеет статус **бета**. Для веб-плагина ChatGPT проверено чтение. Для Cursor Cloud Agents описан отдельный OAuth callback. Актуальные результаты и ограничения по клиентам приведены в [отчёте приёмки](docs/release-1.0.md) и [инструкции по подключению](skills/portable-context/references/connection.md).

### Обновление существующей памяти

1. В действующем клиенте запишите `workspace_id`, HTTPS-адрес или SSH-подключение, SHA-256 одного сохранённого файла, ID и версию страницы вики. Сохраните полный SHA прежнего установщика, приватную папку состояния и копию установленных инструкций с личными правками. Проверьте доступность снимка памяти с оригиналами. Для уже включённого OAuth проверьте также отдельный снимок и комплект восстановления.
2. Возьмите чистый checkout целевого commit. Для управляемой Cloud.ru или SSH-установки запустите из него `python deploy/setup.py --state PRIVATE_STATE update` с **прежней** папкой состояния. Если у памяти 0.9 есть только SSH, сначала проверьте прежний доступ после обновления. Для добавления HTTPS на Cloud.ru отдельно выполните `https-plan`, согласуйте стоимость входа и передайте хэш плана в `install --https --approve-plan REVIEWED_SHA256`. [Порядок установки HTTPS](skills/portable-context/references/deployment.md)
3. Для Timeweb смена закреплённой версии контейнера проходит через `python deploy/setup.py --state PRIVATE_STATE timeweb-update --commit FULL_COMMIT`. После проверки плана повторите команду с `--approve-plan REVIEWED_SHA256`. Для автономной локальной памяти обновите Python-пакет из того же checkout в среде её MCP-сервера и сохраните прежний `--home`. [Операции Timeweb](docs/timeweb-operations.md)
4. Обновите целиком `skills/portable-context` в используемом агенте. Если установлен локальный клиент экспорта, обновите его командой `python deploy/client_setup.py --directory PRIVATE_CLIENT_DIR` с его прежней папкой. Переподключите клиент. Сверьте `memory_status.version`, `skill.recommended_revision`, исходный workspace, вход и разрешения. Скачайте байты контрольного файла, пересчитайте SHA-256 и прочитайте прежнюю ревизию страницы вики.

### Если обновление прервалось или нужен откат

Сначала запишите этап и запустите диагностику с той же папкой состояния. Для продолжения используйте тот же commit, пакет и согласованный план. При частично выполненной миграции оставьте блокировку записи включённой. Для неудачной публикации Timeweb предусмотрен отдельный план повтора. [Продолжение установки](docs/install-resume.md) · [Повтор обновления Timeweb](docs/timeweb-operations.md)

Если требуется вернуться к состоянию до обновления, сохраните текущую установку и восстановите проверенный предшествующий снимок **в отдельную папку или установку** с совместимой версией сервера. Сверьте workspace, скачанный оригинал и вики до переключения клиентов. При потере OAuth используйте комплект восстановления, новый passkey и новое согласие клиентов. Старый сервер нельзя запускать поверх частично обновлённой базы. [Восстановление памяти и оригиналов](skills/portable-context/references/recovery-and-folders.md) · [Восстановление OAuth](docs/oauth-recovery.md)
